# 输入格式规范（一期伤害计算器）

> 状态：v0.1 | 依赖：[方案-打桩伤害链.md](方案-打桩伤害链.md)、[方案-职业专长法术.md](方案-职业专长法术.md) | 最后更新：2026-10-23
> 实现：`engine/calculator.py` | 样例：`../examples/`

一期伤害计算器的定义：

> 输入**固定格式构筑**、**固定格式输出策略**、**固定格式输出环境**，自动输出期望伤害。

三份输入均为 JSON，字段固定。本文规定每一份的字段、类型与语义。

---

## 0. 总览

```
build.json     构筑     ─┐
env.json       输出环境  ├──►  engine/calculator.py ──►  期望伤害 + 追溯
strategy.json  输出策略  ─┘
```

```
python -I engine/calculator.py build.json env.json strategy.json
```

三者职责严格分离：

| 输入 | 决定什么 | 不决定什么 |
| --- | --- | --- |
| 构筑 | 有哪些能力、数值多少 | 打几轮、怎么打 |
| 输出策略 | 每轮做什么、花什么资源 | 目标是什么 |
| 输出环境 | 打谁、打多久、资源节奏 | 你是谁 |

## 1. 构筑（Build）

```jsonc
{
  "meta": {
    "rules_version": "1.63",     // 必填，用于溯源与版本复核
    "level": 4,                  // 必填，总等级
    "point_buy": 32              // 可选，购点上限，仅作记录
  },
  "classes": [
    { "id": "class.barbarian", "level": 4, "subclass": "path.punisher" }
  ],
  "feats": [
    { "id": "feat.威力攻击", "at_level": 1 }
  ],
  "maneuvers": { "known": [], "prepared": [] },
  "spells":   { "known": [], "prepared": [] },
  "items":    [ { "id": "item.greataxe_plus1" } ],

  "scores": {                    // 属性加值分栏，对应角色卡模板
    "base":      { "str": 17, "dex": 13, "con": 16, "int": 10, "wis": 10, "cha": 8 },
    "racial":    { },
    "level_ups": { },
    "feat":      { },
    "item":      { }
  },

  "choices":  { "fighting_style": null },   // 选择类特性（战斗风格、狂暴之心…）
  "variants": [ ],                          // 玩家可选变体开关

  "resources": {                            // 角色拥有的资源池；策略按 id 消耗
    "superiority": {
      "name": "卓越骰",
      "capacity": 3,
      "recharge": "short_rest",             // short_rest | long_rest | per_n_long_rests | per_turn
      "die_faces": 6,                       // 骰面；决定"一枚值多少"
      "unlimited_from_level": null,         // 如狂暴次数 17 级起为「无」
      "derived_from": null,                 // 如超级战技 ["superiority", 10]
      "interval": 1
    }
  },

  "combat": {                    // 战斗时的实际配置
    "weapon": {
      "name": "巨斧+1",
      "kind": "巨斧",             // 武器种类名；武器门控的专长按它匹配
      "dice": "1d12",            // 基础伤害骰
      "damage_type": "slashing",
      "enhancement": 1,          // 魔法增强，同时作用于攻击与伤害
      "ability": "str",          // 攻击所用属性
      "properties": ["双手"],     // 武器属性；触及/速度类专长按它判定
      "reach_ft": 5,             // 基础触及，缺省 5
      "range_ft": null           // 远程射程；近战留空
    },
    "armor": "barbarian_unarmored",
    "shield": false,
    "hit_die_faces": 12,
    "proficient_saves": ["str", "con"],
    "casting_ability": null,        // 施法关键属性；有法术时必须填
    "speed_ft": 30,                 // 步行速度，缺省 30
    "mount": {                      // 坐骑；骑乘时移动力取自坐骑（方案 §2.3）
      "name": "挽马",
      "speed_ft": 60,
      "size": "large",
      "controllable": true
    }
  }
}
```

坐骑速度取自其资料表：矮马 50 尺、挽马 60 尺、乘用马 75 尺。**这个数值直接决定
「反复拉冲」能否持续**——见 §3.10。

### 1.1 字段语义

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `meta.rules_version` | 是 | 规则书版本，算子与数据均锚定于此 |
| `meta.level` | 是 | 总等级；缺省时由 `classes[].level` 之和推出 |
| `scores.*` | 是 | 五栏加值，**引擎只存原始加值，不做隐含推导** |
| `classes[].subclass` | 否 | **必须用规则书里的中文子职名**（如 `神罚者`），不是 slug |
| `choices` | 否 | 多选一的实际选择，键与选项见 §1.3 |
| `variants` | 否 | 形如 `{"scope": "class.barbarian.rage", "id": "variant.swift_rage", "on": false}` |
| `combat.weapon.enhancement` | 否 | 默认 0；**同时加攻击检定与伤害** |
| `combat.weapon.kind` | 否 | 武器类别名（`巨斧` / `长棍` / `巨镰`）。「力满残月」按 `斧` 匹配、「过载震颤」按 `锤` 匹配，类别名含该字即匹配（「斧」匹配巨斧/战斧） |
| `combat.weapon.properties` | 否 | 取值：`双手` / `两用` / `轻型` / `重型` / `灵巧` / `触及` / `投掷` / `弹药` / `装填`。**不写就判定不了**武器门控类特性——校验器会以 NOTE 指出 |
| `combat.armor` | 是 | `none` / `light` / `medium` / `heavy` / `mage_armor` / `monk_unarmored` / `barbarian_unarmored`。含 `unarmored` 的取值视为**未着甲**，无甲移动一类特性照常生效 |

### 1.2 构筑校验：为什么必须单独跑一遍

引擎对**对不上的名字一律宽容**：子职写错不报错，只是拿不到该子职的任何特性；
`choices` 的键写错不报错，只是那个多选一算作没选；专长先决不满足也不报错，
只是白拿一份收益。

宽容在这里是错的——拼写错误、同名不同物、遗漏选择，三者在输出里看起来
都像「构筑本来就这样」，而使用者无法从数字上分辨。

```
python -I engine/build_check.py build.json      # 单独跑
```

`evaluate()` 每次求解也会自动跑一遍，结果并进 `warnings`（ERROR 与 WARN 都进）。

| 级别 | 含义 | 例子 |
| --- | --- | --- |
| ERROR | 一定会算错 | 未知职业 id、总等级与职业等级之和对不上、属性键拼错、专长 id 不存在 |
| WARN | 大概率算错 | 子职名与数据对不上、选项不存在、专长先决未满足、武器属性拼错 |
| NOTE | 可能少算 | 未声明武器种类/属性、该做的多选一没做、未选子职 |

**子职名以数据为准。** 数据里用的是规则书的中文名（`神罚者`、`部族楷模`、
`武士`…），不是 `path.xxx` 这类 slug——写 slug 不会报错，但该子职的特性
一个都不会生效。校验器会把可用名字列出来。

### 1.3 多选一（`choices`）

一条特性有多个互斥选项时，算子里存的是**选项表**，构筑里选的是**名字**：

```jsonc
"choices": {
  "fighting_style": "巨武器战斗",
  "totem_low": "鲨之渴血",
  "qi_element": "火"
}
```

| `choice_key` | 涉及 | 可选 |
| --- | --- | --- |
| `fighting_style` | 狂战士/圣武士/游侠/灵能武士 的 1 级战斗风格 | 对决、巨武器战斗、双武器战斗、投掷武器战斗、防御、守护、拦截、盲斗、箭术、德鲁伊教战士 |
| `spell_style` | 法师/灵能师/牧师 的 1 级法术风格 | 凝神、博闻强识、近程射线、能量回收、法术熟稔、笔走龙蛇、顽强、全身而退、戏法家、勇士祝福、远程医疗 |
| `ancestry_type` | 狂战士·返祖 | 异怪、邪魔、天界、精类、植物、泥怪 |
| `totem_low` / `totem_mid` | 狂战士·兽之形 低/中级 | 熊/鹰/狼/蛇/鲨 各自的两套名字 |
| `beast_weapon` | 狂战士·野兽之形 | 角撞、啃咬、长牙、爪击、蹄击、触须、尾击 |
| `dragon_forge` | 狂战士·龙焰铸就 | 淬炼武器、淬炼护甲 |
| `weapon_lore` | 狂战士·武器学识 | 删除双手/装填/重型、增加双手/投掷/重型/轻型/灵巧/触及、获得熟练 |
| `qi_element` | 武僧·真气属性（侠客） | 木、土、水、火、金 |
| `soul_weapon` | 灵能武士·魂铸武器 | 照明、回力、延展、轰鸣、碎梦、灭形 |
| `rune_pair` | 专长·光之符文 | 威力、优雅、根源、魔法、意志 |
| `guizhen_tier` | 战技·归真 | 放弃额外攻击 / 精通 / 非凡 |
| `qu_se_color` | 战技·取色笔 | 红、橙、其他 |

**同名键可以跨职业共用**（`fighting_style`、`spell_style`）：选项集按职业
各自不同，引擎只挑该构筑真的会拿到的那个算子去匹配选项；
对不上的选项按"未选择"处理并给出 WARN。

### 1.4 属性推导规则

```
属性值 = base + racial + level_ups + feat + item
调整值 = (属性值 − 10) // 2
熟练加值 = 2 + (等级 − 1) // 4
```

### 1.5 触及与速度：为什么它们会影响 DPR

两者都不直接加伤害，但决定**这一轮够不够得着**：

```
目标在 30 尺外，速度 30 → 这轮靠近 30 尺即贴身
目标在 40 尺外，速度 30 → 靠近 30 尺后还剩 10 尺，触及 5 尺打不到 → 本轮 0 伤害
同一目标，速度 45     → 走满 40 尺，正常攻击
```

触及同理：目标在 10 尺外，触及 5 尺打不到，触及 15 尺（斗气外放）可以。

**这两项由构筑累加，不由策略声明。** 专长与职业特性通过
`reach_bonus_ft` / `speed_bonus_ft` 修改，引擎逐轮重算速度——
狂暴、点燃这类只在生效期间给移速的增益，写在构筑层会让没开 buff 的回合也快跑。

武器门控（`weapon_selector`）在累加时就生效：「长度优势」只在长棍或触及武器上给
+5 尺，拿巨剑时不但不给，还会在 `warnings` 里说明——**门控挡下的事必须说出来**。

### 1.6 为什么 `scores` 分五栏

规则书角色卡模板本来就按「初始 / 种族+ / 升级+ / 专长+ / 装备+」分栏。合并成一栏会丢失来源，
违反"每个派生值可追溯"的要求——攻击加值必须能打印成
`力量调整值+3 + 熟练加值+2 + 武器增强+1 = +6`。

### 1.7 资源：跨轮才算得清

资源的价值只在**跨轮累计**时成立。一轮里用了几个卓越骰无所谓，
一场下来还剩几个才是约束。因此资源池分三类来源：

| 来源 | 谁提供 | 例子 |
| --- | --- | --- |
| 职业表推导 | 引擎自动，**不必手写** | 狂暴次数（狂战士职业表「狂暴次数」列，17 级起 ∞） |
| 构筑声明 | `resources.<池 id>` | 卓越骰、法术位、专长限次 |
| 特性推导 | 引擎自动，来自算子的 `uses` | 连刺次数等 |

**法术位按环阶分账**，命名约定 `spell_slots_<环阶>`：

```jsonc
"resources": {
  "spell_slots_1": { "name": "1环法术位", "capacity": 4, "recharge": "long_rest" },
  "spell_slots_2": { "name": "2环法术位", "capacity": 3, "recharge": "long_rest" },
  "spell_slots_3": { "name": "3环法术位", "capacity": 2, "recharge": "long_rest" }
}
```

职业表只给「法术位」总数，不给分环明细，所以这一项必须由构筑声明。
**声明之后施放会自动扣**：`save_effects[].slot_level` 与
`per_attack.slot_level` 各扣 1 个对应环阶——不需要在 `spends` 里手抄。
漏声明会在输出里告警，而不是静默当作免费施法。

**次数型资源在「激活」时扣，不是每轮扣。** 狂暴持续 1 分钟，
连续 5 轮都列在 `buffs` 里只消耗 1 次；中断后重开会再扣一次。

短休次数 `env.short_rests` 决定短休池在一次求解窗口内的有效容量
（容量 ×(短休次数+1)），长休同理走 `env.long_rests`。

超限**告警但照算**——这是既有约定（策略声明值超过推导值也一样）。
输出里的 `警告` 一栏就是让使用者决定信不信这个数字的地方。

## 2. 输出环境（Environment）

对应方案 §5.2 的 `TargetProfile`。

```jsonc
{
  "target": {
    "count": 1,
    "ac": 15,
    "saves": { "str": 0, "dex": 0, "con": 0, "int": 0, "wis": 0, "cha": 0 },
    "resist": [],                 // 伤害类型列表
    "vuln": [],
    "immune": [],
    "absorb": [],
    "pre_reduction":  { },        // 抗性之前扣减，如 {"all": 5}
    "post_reduction": { }         // 抗性之后扣减，如 {"slashing": 3}
  },
  "range_band": "engage",         // engage | move | ranged
  "initial_distance_ft": 30,
  "terrain": "open",              // open | difficult | restricted
  "rounds": 1,
  "short_rests": 0,
  "prebuff_rounds": 0
}
```

### 2.1 字段语义

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `target.ac` | 是 | 护甲等级 |
| `target.resist` / `vuln` / `immune` / `absorb` | 否 | 按**伤害类型**列举；吸收优先级高于免疫 |
| `target.pre_reduction` | 否 | 在抗性/易伤**之前**扣减（规则书例：所有伤害减少 5 的灵光） |
| `target.post_reduction` | 否 | 在抗性/易伤**之后**扣减（规则书例：战斗风格"拦截"） |
| `rounds` | 是 | 评分时间窗，即打几轮 |
| `enemy_triggers_per_round` | 否 | 每轮引发你借机攻击的次数，默认 **0**。打桩下目标不动不还手，不声明就不产生借机攻击收益。等价于 `enemy_triggers.retreat` |
| `enemy_triggers` | 否 | 按**触发源**分列的敌人行为次数（见 §2.2）。"敌人攻击你 3 次"和"敌人离开你的触及 3 次"对同一个构筑是两回事，不能合成一个数 |
| `target_leaves_areas` | 否 | 默认 `false`。目标是否会脱离持续区域（匕首之云、月华之光…）。打桩契约下目标不移动，故默认留在区域内、每轮再吃一次伤害；声明为 `true` 则只在施放那一轮结算 |
| `ally_within_5ft_of_target` | 否 | 默认 `false`。目标 5 尺内是否有能行动的友方——盗贼「偷袭」的夹击路径靠它判定。**不声明就拿不到夹击偷袭**，这是环境事实，不该由工具假设 |
| `short_rests` | 否 | 期间短休次数，决定短休池的有效容量 |
| `initial_distance_ft` | 否 | 默认 30；打桩契约第 4 条 |

**两类减伤必须分开**，这不是可选优化。规则书对两者的先后有明确规定，
合并成一个字段会算错。

### 2.2 借机攻击的触发源

打桩契约下目标不动手，所以借机攻击必须**由环境声明"敌人做了什么"**，
再由构筑决定"哪些能做反应"。环境只描述事件，不预先假设你的构筑能利用它们。

```jsonc
"enemy_triggers": {
  "retreat": 2,            // 敌人移动离开你的触及
  "approach": 1,           // 敌人移动进入你的触及
  "cast_spell": 1,         // 敌人施放法术
  "activate_program": 0,   // 敌人激活程序
  "attack_you": 3,         // 敌人攻击你（无论命中与否）
  "use_object": 0          // 敌人使用物件 / 启动魔法物品
}
```

| 触发源 | 基础规则 | 需要专长 |
| --- | --- | --- |
| `retreat` | ✅ 人人可反应 | — |
| `approach` | ❌ | 坚守阵地 |
| `cast_spell` | ❌ | 巫师杀手 |
| `activate_program` | ❌ | 程序员杀手 |
| `attack_you` | ❌ | 罗比拉战术 |
| `use_object` | ❌ | 缠蛇掠血（且须持用长鞭） |

没有对应专长时，该触发**不产生伤害**，并在 `trace` 里写明原因；
武器不符时进 `warnings`。这不是静默丢弃——写进环境就一定会出现在报告里。

预算仍然是 `1 次反应 + 专长追加`，单次触发打几击由专长决定
（连续借机 = 2 击，占 2 次次数）。**触发再多也超不过预算。**

## 3. 输出策略（Strategy）

```jsonc
{
  "meta": { "name": "鲁莽攻击 + 威力攻击" },
  "rounds": [
    {
      "round": 1,
      "buffs": ["rage", "reckless"],           // 本轮生效的状态
      "action": "act.mounted_charge",          // 复合动作（可选），如骑乘冲刺
      "move": { "toward": true, "ft": 25 },    // 本轮移动；不写则不移动
      "spends": { "superiority": 1 },          // 本轮资源消耗，按池 id
      "attacks": 1,                            // 本轮攻击次数
      "per_attack": {
        "adv_tiers": 1,                        // 每次攻击的优势层数
        "ops": ["feat.凶蛮打手", "feat.威力攻击"]  // 作用于每次攻击的算子
      },
      "contingencies": [                       // 条件策略（可选）
        { "trigger": "hit_or_crit", "attack": 0,
          "spend": { "superiority": 1 },
          "extra_dice": [{ "dice": "1d8", "damage_type": "slashing" }],
          "name": "卓越骰加伤" }
      ],
      "steps": [                               // 动作经济声明（可选，用于校验）
        { "name": "骑乘冲刺", "cost": { "action": 1 }, "group": "charge" },
        { "name": "攻击", "cost": { "replace_attack": 1 }, "group": "charge" }
      ]
    }
  ]
}
```

### 3.1 字段语义

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `rounds[].round` | 否 | 轮次序号，缺省按数组顺序 |
| `rounds[].buffs` | 否 | 增益名或算子 id。短名 `rage` / `reckless` 会解析为对应职业特性算子 |
| `rounds[].move` | 否 | `{"toward": true, "ft": 25}`；不写则不移动，**超出触及/射程会告警并记 0 次攻击** |
| `rounds[].spends` | 否 | `{池 id: 数量}`；与构筑的 `resources` 对照校验总量与单轮上限 |
| `rounds[].attacks` | 否 | 本轮攻击次数。**省略时由职业特性推导**（见 §3.11）；声明值超过推导值会告警 |
| `rounds[].save_effects` | 否 | 豁免型效果列表，见 §3.3 |
| `rounds[].save_ops` | 否 | 作用于本轮所有豁免效果的修正算子，如 `feat.威力豁免` |
| `rounds[].action` | 否 | 复合动作算子 id，见 §3.6 |
| `rounds[].contingencies` | 否 | 条件策略，见 §3.7 |
| `rounds[].steps` | 否 | 动作经济声明，见 §3.8 |
| `rounds[].per_attack.adv_tiers` | 否 | 优势层数，整数，可为负 |
| `rounds[].per_attack.ops` | 否 | 算子 id 列表，按顺序作用到每次攻击 |

**算子从 `形式化/ops/*.json` 读取，不写死在代码里。** 策略只引用 id。

### 3.2 算子如何生效

| 算子字段 | 作用 |
| --- | --- |
| `projection.attack_bonus` | 加到攻击加值（威力攻击 = −5） |
| `projection.adv_tiers` | 加到优势层数 |
| `projection.damage_slots[]` | 伤害加值；`cap` 与 `cap_scaling` 按等级封顶 |
| `projection.extra_dice[]` | 附伤骰；`limit: "每回合一次"` 时只作用于本轮第一次攻击 |

### 3.3 豁免型效果

攻击检定之外的伤害路径，用于法术与部分能力：

```jsonc
"save_effects": [
  { "spell": "sp.火球术", "slot_level": 3 }        // 引用法术算子（推荐）
]
```

也支持内联写明，适合尚未编译成算子的临时效果：

```jsonc
"save_effects": [
  { "dc": 15, "save": "dex", "dice": "8d6",
    "half_on_save": true, "damage_type": "fire" }
]
```

`half_on_save` 必须是显式字段，不能从文本推断——它直接改变期望值公式：

```
E = P(失败) × 伤害 + P(成功) × (半伤 ? 伤害/2 : 0)
```

半伤按目标端结算口径向下取整。

### 3.4 攻击型法术

```jsonc
"per_attack": { "kind": "spell_attack", "spell": "sp.冻寒之触", "slot_level": null }
```

- `kind` 为 `spell_attack` 时，攻击加值改用**法术攻击加值**（熟练 + 施法关键属性）。
- 伤害骰由法术算子给出，并按角色等级应用 `scaling`、按 `slot_level` 应用 `upcast`。
- 攻击实例数由算子的 `attack.count` 决定（灼热射线 3 道），升环加道用 `upcast.add_count_per_slot`。
- 算子的 `attack.auto_hit` 为真时**不掷攻击检定**，因此**不会重击**（魔法飞弹）。
  枚数按法术位查表时用 `attack.count_by_slot`。
- **距离判定用该法术自己的施法距离**，不是武器的触及/射程。早期实现误用武器射程，
  导致 120 尺的戏法被 5 尺法杖挡住，已修正。

### 3.6 复合动作

有些动作不是"修改一次攻击"，而是**改变回合结构**。骑乘冲刺即为一例：

```jsonc
"action": "act.mounted_charge"
```

算子用 `composite` 描述其约束：

```jsonc
"composite": {
  "move":   { "min_travel_ft": 30, "straight": true },
  "attack": { "count": 1, "overrides_extra_attack": true, "adv_tiers": 1 }
}
```

计算器据此：
- 校验本回合直线移动量不足 `min_travel_ft` 时**不生效并告警**；
- 攻击次数被压到 `count`，即使构筑有额外攻击；
- 附加 `adv_tiers`；
- 若构筑带 `feat.骑乘战斗`，该次攻击的目标获得对钝击/挥砍/穿刺易伤。

### 3.7 条件策略

限次资源的价值取决于花在什么结果上（D-018）。`contingencies` 表达这种分支：

```jsonc
{ "trigger": "hit_or_crit",   // miss | hit | crit | hit_or_crit
  "attack": 0,                // 作用于第几次攻击；省略则每次都可
  "spend": { "superiority": 1 },
  "extra_dice": [{ "dice": "1d8", "damage_type": "slashing" }],
  "next_adv": 0,              // 对后续攻击的优势层数影响
  "name": "卓越骰加伤" }
```

**消耗只在触发时计入**，因此"命中了才花骰子"与"无论如何都花"的期望值不同。

### 3.8 动作经济声明

`steps` 让计算器校验槽位与替换攻击的合法性：

```jsonc
"steps": [
  { "name": "骑乘冲刺", "cost": { "action": 1 }, "group": "charge" },
  { "name": "攻击", "cost": { "replace_attack": 1 }, "group": "charge" }
]
```

可检出的违规：槽位重复、动作组内插入附赠动作、替换攻击超出本轮可用次数。

### 3.10 冲刺后的移动（`post_move`）

骑乘冲刺的流程有严格顺序：先移动、再攻击，**剩余移动力只能在攻击之后使用**。

```jsonc
"round": 1,
"action": "act.mounted_charge",
"move":      { "toward": true,  "ft": 30 },   // 冲刺
"post_move": { "toward": false, "ft": 30 }    // 攻击后退开
```

这条规则决定了「反复拉冲」的可持续性：

| 坐骑速度 | 冲刺 30 尺后剩余 | 能否退到 30 尺外 | 结果 |
| --- | --- | --- | --- |
| 50 尺（矮马） | 20 尺 | 否 | **隔轮才能再冲**，三轮只冲两次 |
| 60 尺（挽马） | 30 尺 | 是 | 每轮都能冲 |
| 75 尺（乘用马） | 45 尺 | 是 | 每轮都能冲，且有余量 |

实测三轮期望伤害：挽马 86.49、矮马 57.66。**差距不是线性的**——是"能不能冲"的开关。

另有两条硬约束：
- 冲刺要求**起点距目标至少 30 尺**，跑不出这个距离就冲不起来；
- 靠近时实际位移受当前距离限制：距目标 20 尺时，走 30 尺的指令只移动 20 尺。
  早期实现按满额计入移动量，导致慢速坐骑的可持续性被高估。

### 3.11 攻击次数由职业特性推导

策略**不需要**写死攻击次数。构筑写出"职业 + 等级"，次数由已获得的职业特性算子决定：

```
攻击次数 = max(1, 所有已获得特性中 attack_count 的最大值)
```

例：狂战士 5 级获得「额外攻击」（`attack_count: 2`），推导结果为 2；
再叠加骑乘冲刺的 `attack.count: 1` 后压回 1 次。

```
攻击次数由职业特性决定：2（额外攻击）
第 1 轮 骑乘冲刺 覆盖额外攻击：2 次 → 1 次
```

若策略显式声明了 `attacks` 且超过推导值，计算器**告警并仍按声明值计算**——
不静默修正，因为超出的次数可能是尚未编译的特性，需要人工判断。

### 3.12 增益映射

`buffs` 里的短名会解析为算子 id：

| 短名 | 算子 | 效果 |
| --- | --- | --- |
| `rage` | `cf.狂战士.狂暴` | 启用职业表的狂暴伤害加值 |
| `reckless` | `cf.狂战士.鲁莽攻击` | +1 重优势 |

**增益的效果由算子携带，不要在策略里重复手写。** 早期样例同时写了
`buffs: ["reckless"]` 和 `per_attack.adv_tiers: 1`，解析短名后变成 2 重优势——
这是典型的格式漂移，已修正。

### 3.13 策略与构筑的配对

策略的 `meta.requires_build` 指明它对应哪份构筑：

```jsonc
"meta": { "requires_build": "barbarian_l4.build.json" }
```

`tools/check_interfaces.py` 据此检查资源池是否声明、法术是否具备施法属性。

### 3.14 跨轮状态

有些效果的值不取决于"这一轮怎么打"，而取决于**之前几轮发生过什么**。
引擎为此维护三类跨轮状态——它们都不需要写在策略里，但**写错策略会让它们失效**。

| 状态 | 谁在用 | 生命周期 |
| --- | --- | --- |
| **连击计数** | 暴雨梨花（连续第 X 次命中额外 2×X） | 整场战斗累计；失手归零 |
| **增益起始轮** | 恶魔形态（第 X 轮额外 X×10） | 从该增益第一次出现在 `buffs` 的那一轮起算 |
| **专注** | 一切带 `concentration` 的法术 | 同时只能有一个，新的顶掉旧的 |

三点需要说清楚：

**连击跨轮延续。** 规则书写的是"失手或骰先攻时归零"，也就是轮与轮之间
不清零。每轮独立求值会把这条链切断，第 2 轮又从 X=1 开始。
引擎跨轮传递的是连击数的**期望**而不是某一条抽样路径——好在伤害对连击数
是线性的（额外 2×X），`E[2×(S+k)] = 2·E[S] + 2·k`，所以带期望值是精确的。

**增益从它自己开始的那一轮计时。** 第 5 轮才开的恶魔形态，第 5 轮是 X=1，
不是 X=5。策略里把 `buffs` 写成从第几轮出现，计时就从那一轮起算。

**专注是互斥的。** 施放新的专注法术会中断旧的，旧法术维持的持续区域一并结束。
早先只告警不处理，等于让两个专注同时生效——这不是"保守"，是把伤害凭空推高。
重施**同一个**专注法术算替换：本轮的维持结算改为施放伤害，不叠加。

持续区域（`recurring`）与专注相互独立：区域是否随专注结束，看该法术本身
有没有 `concentration` 标记。月华之光在本数据里是"1 分钟"而非专注法术，
所以别的专注法术施放时它照常持续。


## 4. 输出（Result）

计算器输出三部分：

```
输入追溯                       ← 每一项派生值的来源
  等级 4
  熟练加值 +2
  AC 14
  HP 46
  攻击加值：力量调整值+3 + 熟练加值+2 + 武器增强+1 = +6
  目标 AC 15
  第 1 轮：1 次攻击（狂暴），feat.凶蛮打手、feat.威力攻击 → 17.145

期望伤害合计: 17.145
平均每轮:     17.145
结果树叶子:   3                 ← 计算路径可核查
```

`结果树叶子` 是可信度指标：一轮 k 次攻击有 3^k 个结果叶子，
叶子数对上说明枚举完整，而不是悄悄退化成近似。
