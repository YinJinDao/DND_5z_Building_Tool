## 一、未形式化的覆盖缺口

### 1.1 总量

| 类别 | 入库 | A 档 | A 档已编译 | A 档覆盖率 |

| 战技 | 258 | 59 | 16 | 27.1% |
| 职业特性 | 475 | 111 | 2 | 1.8% |
| 专长 | 672 | 139 | 4 | 2.9% |
| 法术 | 1103 | 455 | 244 | 53.6% |
| **合计** | **2508** | **764** | **266** | **34.8%** |

**战技 A 档已完成全部定性**，每条都有明确结论：

| 结论 | 条数 | 含义 |
| --- | ---: | --- |
| `modeled` | 15 | 已编译为算子 |
| `needs_ruling` | 37 | 有明确原因，需裁定或引擎扩展 |
| `out_of_scope` | 7 | 原文明确不造成伤害 |

`needs_ruling` 的原因分布（37 条）：结构未匹配已知模式 19、依赖对抗检定 3、
公式型伤害 3（引擎已支持但文本未自动识别）、伤害来自友方 3、即死 2，
其余为多实例、多选一、夹击前提等个例。

**这意味着"战技全量编译"的天花板比我原先估计的低**：59 条 A 档里只有 12 条
（20%）是纯骰式结构，其余需要对抗检定分布、查表、公式表达式或状态化建模。

### 1.2 分项

**战技：12 / 59（A 档）。** 已编译：英勇冲锋、终结之舞、回马枪、巴之雷、力劈华山
（手工）+ 惩戒之姿、百川归海、全力以赴、椎骨幻兵、碎刃、闪电旋风劈、战鼓擂（按模式生成）。

**编译过程中的一个重要发现**：抽取器漏掉了 6 条战技。原因是规则书把「超级」写成了
「超极」（错别字），头部正则认不出，这些条目不仅没被抽取，**文本还串进了前一条战技**。
修正后 252 → 258 条，`坟压` 的正文从 724 字缩回 211 字。

**职业特性：6 / 475。** 已编译全部为狂战士主职（狂暴、鲁莽攻击、额外攻击三档）加神罚者一条。

**子职特性：1 / 316。** 几乎空白。子职是构筑差异的主要来源，这块不补，三七期的构筑搜索无从谈起。

**法术：244 / 455（A 档）。** 用 `tools/compile_spells.py` 批量编译。
法术的结构远比对战技规整：A 档 455 条中 **279 条是"攻击/豁免 + 骰式伤害"**（61%），
而战技只有 20%。最终 `modeled` 244 / `needs_ruling` 116 / `out_of_scope` 95。

**批量编译踩到两个系统性 bug**：

| bug | 影响 |
| --- | --- |
| 把「自身（半径10尺）」的区域半径当成施法距离 | **27 条**区域法术在 30 尺外一律记 0 伤害 |
| 施法者可选伤害类型的法术取了文本里第一个类型 | 45 条法术在目标有抗性时被系统性低估 |

前者靠随机抽验发现（一条 0.000 很扎眼），后者靠"多骰式+多类型"专项筛查发现。
两处都改成了通用处理：`_range_ft` 识别自身范围；`type_choice` 按目标抗性择优。

### 1.3 尚不能表达的能力（比数量缺口更关键）

即使数量补上，以下能力**当前引擎无法表达**，需要先扩引擎：

| 能力 | 涉及范围 | 现状 |
| --- | --- | --- |
| 专注 | 大量法术 | **冲突检测已实现**（同时只能维持一个，冲突则告警）。但持续效果模型未建——当前专注类法术没有可跨轮延续的伤害，故机制处于待激活状态 |
| 召唤物 / 坐骑以外的伙伴 | 兽王、召唤类 | 未建模 |
| 光环 / 范围增益 | 圣武士、吟游诗人 | 未建模（打桩单角色，部分可忽略） |
| 条件触发链（"如果…则…"跨攻击） | 多个专长 | `Rule` 支持单层，多层触发未验证 |
| 资源在攻击之间分配 | 卓越骰核心用法 | 策略层只支持按轮声明，不支持"这一击用几枚" |

**专注是最该先补的**：它影响可选的策略组合，不只是单条法术的数值。

## 二、算子审计

对 18 个算子做机器审计（projection 字段全集 vs 引擎实际引用），加上人工复核，得出 7 项。

### 2.1 已修复（本轮）

| # | 问题 | 性质 | 处理 |
| --- | --- | --- | --- |
| 1 | `cf.神罚者.神性之怒` 与数据 id `cf.狂战士.神性之怒` 对不上 | **静默失效** | 改名；并新增检查 A10 专防此类 |
| 2 | `ability_bonus`（凶蛮打手 +1 属性）引擎从未处理 | **静默失效** | 新增构筑期效果结算 `apply_build_time_effects` |
| 3 | 引擎硬编码 `"cf.狂战士.狂暴"` 判断是否狂暴 | 耦合 | 改为"增益算子带 `rage` 键即生效" |
| 4 | 引擎硬编码 `"feat.骑乘战斗"` 取易伤 | 耦合 | 算子改声明 `on_hit_target_vuln.trigger`，引擎按 trigger 通用匹配 |
| 5 | `rage.damage_bonus_table` 是引擎无法解析的字符串指针 | 死字段 | 改为 `damage_bonus_from: "class_table"` + 列名，语义明确 |
| 6 | `attack_count_mode` 恒为 `max` 且引擎不读 | 死字段 | 删除 |
| 7 | `extra_dice.slot` 被丢弃，附伤丢失来源 | 可追溯性 | 优先取算子声明的 slot，否则回落到算子 id |

**第 1、2 条都是"数值缺失但不报错"**：神性之怒编译了却永远匹配不到构筑；
凶蛮打手的属性加值从未生效。这类问题只能靠审计发现，不能靠测试——因为测试用的是同一套错误假设。

### 2.2 可以考虑但**不建议**做的合并

**额外攻击 / 精通额外攻击 / 非凡额外攻击** —— 三个文件，同一机制，只差 `attack_count`（2/3/4）。

可以合并成一个算子加等级表，但**建议保留分开**：

- 每个算子的 `acquisition.level` 精确对应一条数据条目，id 一一对应；
- 有了这个对应，覆盖统计与 A10 检查才能自动化；
- 合并后 `acquisition.level` 语义变模糊（一个算子对应三个等级门槛），反而要引入新字段表达。

**文件数不是成本，可自动化的对应关系才是收益。** 这条取舍记在此处，避免后来者重复讨论。

### 2.3 需要补充的

| 项 | 说明 | 优先级 |
| --- | --- | --- |
| 专注状态 | 影响策略可选空间，不只是数值 | 高 |
| 卓越骰在攻击间分配 | 「命中才花」已支持，「花几枚」尚不支持 | 高 |
| 多层触发链 | 当前 `Rule` 只能单层 | 中 |
| 算子的 `gate` 字段 | 多数算子写了 gate，引擎只检查了 `requires_rage` / `mounted` | 部分完成 |
| 变体开关接入 | `variants` 在构筑格式里，算子无对应处理 | 低 |

`gate` 原先是**声明了但不检查**的：策略可以在没开狂暴时使用要求狂暴的算子而不报错。
已补：算子生效前校验 gate，不满足则告警并跳过。实测「神性之怒」未开狂暴时
8.375 → 开狂暴后 13.800，且前者的告警正确。

仍待补的 gate 项：`weapon.kind`（武器类型）、`distance`（距离区间）在算子层尚未统一校验。

### 3.1 关于"全部编译"的现实判断

战技 A 档做完后的结论是：**纯骰式结构只占约 20%**。其余需要的是**引擎能力**而非更多人手：

| 缺失能力 | 阻塞的 A 档战技 | 状态 |
| --- | ---: | --- |
| 伤害查表（体型/材质/临时生命值） | 2 | **已支持** |
| 公式型伤害（速度/2.5 等） | 3 | **已支持** |
| 对抗检定分布（运动 vs 运动/体操） | 3 | **已支持** |
| 多实例分别结算 | 1 | 未支持 |
| 状态化触发（消耗、位移累加） | 3 | 未支持 |

**伤害查表与公式型伤害已落地**，对应引擎能力：

- `damage_tables.jsonl`：结构化伤害表，支持交叉表（体型 × 材质）与分档表（临时生命值）
- `eval_formula`：受限命名空间的公式求值，支持 `speed`、`level`、`min/max`
- 算子用 `damage_replaces_weapon` + `damage_table` / `formula_damage` 声明

已据此编译：泰山压顶（体型×材质交叉表）、长城（临时生命值分档）、
苍鹰击于殿（速度/2.5 公式）。

**对抗检定分布已落地**（`engine/combat.py`）：

- `d20_tier_distribution`：优/劣势下 d20 的完整分布（n 重优势 = 取 n+1 枚最高）
- `opposed_win_probability`：P(攻方 > 守方)，平手判守方胜（规则书写「若你胜出」）
- 支持卓越骰加入检定、守方在多个技能中择优（取对攻方最不利者）

实现中踩到一个错：`roll_dist` 闭包复用了攻方的优势分布，导致**守方也被赋予优势**，
两边抵消。表现是"攻方有优势时胜率反而不变"，很容易被当成合理结果放过。

战技据此按胜率加权：泰山压顶 10.5 → 9.15（胜率 0.8717）。
