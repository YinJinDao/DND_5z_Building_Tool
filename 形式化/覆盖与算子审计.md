## 一、未形式化的覆盖缺口

A 档（必进队列）完成率 **2.2%**。这是当前最大的结构性缺口。

### 1.2 分项

**战技：5 / 252。** 已编译 A 档第一批：英勇冲锋、终结之舞、回马枪、巴之雷、力劈华山。
选取依据是**模式覆盖率**——25 条 A 档战技用「N 枚卓越骰的骰值」作伤害，
其中 9 条是"攻击 + 卓越骰加伤"结构，先打通这条主干。

**职业特性：6 / 475。** 已编译全部为狂战士主职（狂暴、鲁莽攻击、额外攻击三档）加神罚者一条。

**子职特性：1 / 316。** 几乎空白。子职是构筑差异的主要来源，这块不补，三七期的构筑搜索无从谈起。

**法术：5 / 1103。** 只覆盖了攻击型、豁免型、自动命中、多射线四种路径的代表各一条。

### 1.3 尚不能表达的能力（比数量缺口更关键）

即使数量补上，以下能力**当前引擎无法表达**，需要先扩引擎：

| 能力 | 涉及范围 | 现状 |
| --- | --- | --- |
| 专注 | 大量法术 | **冲突检测已实现**（同时只能维持一个，冲突则告警）。但持续效果模型未建——当前专注类法术没有可跨轮延续的伤害，故机制处于待激活状态 |
| 召唤物 / 坐骑以外的伙伴 | 兽王、召唤类 | 未建模 |
| 光环 / 范围增益 | 圣武士、吟游诗人 | 未建模（打桩单角色，部分可忽略） |
| 条件触发链（"如果…则…"跨攻击） | 多个专长 | `Rule` 支持单层，多层触发未验证 |
| 资源在攻击之间分配 | 卓越骰核心用法 | 策略层只支持按轮声明，不支持"这一击用几枚" |

**专注是最该先补的**：它影响可选的策略组合，不只是单条法术的数值。

## 二、算子审计

对 18 个算子做机器审计（projection 字段全集 vs 引擎实际引用），加上人工复核，得出 7 项。

### 2.1 已修复（本轮）

| # | 问题 | 性质 | 处理 |
| --- | --- | --- | --- |
| 1 | `cf.神罚者.神性之怒` 与数据 id `cf.狂战士.神性之怒` 对不上 | **静默失效** | 改名；并新增检查 A10 专防此类 |
| 2 | `ability_bonus`（凶蛮打手 +1 属性）引擎从未处理 | **静默失效** | 新增构筑期效果结算 `apply_build_time_effects` |
| 3 | 引擎硬编码 `"cf.狂战士.狂暴"` 判断是否狂暴 | 耦合 | 改为"增益算子带 `rage` 键即生效" |
| 4 | 引擎硬编码 `"feat.骑乘战斗"` 取易伤 | 耦合 | 算子改声明 `on_hit_target_vuln.trigger`，引擎按 trigger 通用匹配 |
| 5 | `rage.damage_bonus_table` 是引擎无法解析的字符串指针 | 死字段 | 改为 `damage_bonus_from: "class_table"` + 列名，语义明确 |
| 6 | `attack_count_mode` 恒为 `max` 且引擎不读 | 死字段 | 删除 |
| 7 | `extra_dice.slot` 被丢弃，附伤丢失来源 | 可追溯性 | 优先取算子声明的 slot，否则回落到算子 id |

**第 1、2 条都是"数值缺失但不报错"**：神性之怒编译了却永远匹配不到构筑；
凶蛮打手的属性加值从未生效。这类问题只能靠审计发现，不能靠测试——因为测试用的是同一套错误假设。

### 2.2 可以考虑但**不建议**做的合并

**额外攻击 / 精通额外攻击 / 非凡额外攻击** —— 三个文件，同一机制，只差 `attack_count`（2/3/4）。

可以合并成一个算子加等级表，但**建议保留分开**：

- 每个算子的 `acquisition.level` 精确对应一条数据条目，id 一一对应；
- 有了这个对应，覆盖统计与 A10 检查才能自动化；
- 合并后 `acquisition.level` 语义变模糊（一个算子对应三个等级门槛），反而要引入新字段表达。

**文件数不是成本，可自动化的对应关系才是收益。** 这条取舍记在此处，避免后来者重复讨论。

### 2.3 需要补充的

| 项 | 说明 | 优先级 |
| --- | --- | --- |
| 专注状态 | 影响策略可选空间，不只是数值 | 高 |
| 卓越骰在攻击间分配 | 「命中才花」已支持，「花几枚」尚不支持 | 高 |
| 多层触发链 | 当前 `Rule` 只能单层 | 中 |
| 算子的 `gate` 字段 | 多数算子写了 gate，引擎只检查了 `requires_rage` / `mounted` | 部分完成 |
| 变体开关接入 | `variants` 在构筑格式里，算子无对应处理 | 低 |

`gate` 原先是**声明了但不检查**的：策略可以在没开狂暴时使用要求狂暴的算子而不报错。
已补：算子生效前校验 gate，不满足则告警并跳过。实测「神性之怒」未开狂暴时
8.375 → 开狂暴后 13.800，且前者的告警正确。

仍待补的 gate 项：`weapon.kind`（武器类型）、`distance`（距离区间）在算子层尚未统一校验。
