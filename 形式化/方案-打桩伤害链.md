# 方案：打桩伤害链的形式化

> 状态：v0.2（已纳入 2026-10-23 评审意见） | 依赖：[回归用例.md](回归用例.md)、[数据库.md](数据库.md)、[决策记录 D-011~D-019](../plans/决策记录.md) | 最后更新：2026-10-23
> 适用规则书版本：`docs/5z规则1.63版.chm`（v1.63，2026-10-21）

本文给出「打击者打桩伤害链」的形式化方案：把规则书中与伤害计算相关的内容，转成可计算、可校验、可审计的结构。

本文定义**数据模型与语义**，不规定实现方案与阶段划分（按 `plans/` 的治理原则，这些在阶段实际创建时再定）。

---

## 1. 为什么收窄范围

规则书解包后共 **1338 个 HTML 文件**（职业 209、法术 107、怪物 69、专长 67、种族 65、装备 60、世界 42、基础 23、私货未通过 16、范例卡 2），另有 1166 行法术词典。

直接建通用规则引擎不划算：

1. **体量**：约 3000 个 crunch 条目，绝大多数是独一无二的自然语言描述。
2. **歧义**：规则书自带 `//` 注释、"疑难解答"章节与"玩家可选变体"，说明边界本身模糊。
3. **版本漂移**：v1.63 仅相对上一版就修改了夹击加值（+3→+2）、狂战士 2 级特性、多处战技与法术数值。一次性编译的产物必然腐烂。

因此立场是：

> **要形式化的不是"5z 规则"，而是"5z 中影响伤害的那个子语言"。**

## 2. 打桩契约

所有计算结果都条件于以下假设。**这份契约必须随结果一同呈现**，否则数值没有意义。

| # | 假设 |
| --- | --- |
| 1 | 单目标；固定 AC、六项豁免、伤害抗性/易伤/免疫/吸收 |
| 2 | 目标不行动、不还手、不移动、不施加状态、不产生反应 |
| 3 | **场地无限大**：无墙、无边界、无地形障碍；地形效果可作为环境轴显式开启 |
| 4 | **初始距离固定**（默认 30 尺）；求解过程中**追踪相对距离** |
| 5 | 目标不移动，因此相对距离只由攻击者的移动改变 |
| 6 | 无掩护、无夹击、无盟友（除非环境显式声明） |
| 7 | 目标初始无状态；攻击者可利用 `prebuff_rounds` 轮进行准备 |
| 8 | **只有构筑付出了代价才施加的状态计入** — 不得无偿获得倒地等状态带来的优势 |
| 9 | 攻击者先手，不掷先攻 |
| 10 | 目标 HP 视为充足（除非需要计算击杀轮数） |
| 11 | 开战时资源为满；战斗期间的短休次数由环境给定 |

### 2.1 第 8 条是公平性锚点

打桩时目标不会抵抗。若不约束，任何构筑都能免费把目标设为倒地、束缚、恐慌以获取优势，结果将失去比较意义。规则是：**状态必须由构筑中的某个算子以明确的动作/资源代价产生**。

### 2.2 距离与移动模型

不做网格，但**必须追踪距离**。理由：规则中存在大量位移依赖的伤害循环（冲锋、骑乘冲锋、俯冲、拉开距离后投掷），把这些一律排除会误杀真实构筑。

模型：

- 状态含一个标量 `distance`（尺）。
- 每回合移动力 = 速度（含修正），未用完消失。
- 移动是一个算子，改变 `distance`。
- 攻击要求 `distance ≤ 触及` 或 `distance ≤ 射程`；超出射程的攻击不可选。
- 冲锋类算子要求"先直线移动至少 N 尺再攻击"，形式化为前置条件 `min_travel`。
- 场地无限大 ⇒ 距离永远可以自由调整，**不含地形阻塞**；地形若有影响，通过环境轴开启（如 `terrain: open | difficult | restricted`）。

**这样 T1（骑乘反复拉冲）可以复现，且复现条件被显式写出来，而不是隐含在"理想情况下"里。**

### 2.3 骑乘（依据「基础/战斗/骑乘」）

坐骑不是背景设定，而是**改变移动力来源与可用动作项**的一等状态。

| 规则 | 形式化含义 |
| --- | --- |
| 坐骑需体型比骑手大至少一级、身体结构合适（有水平背部）、非虚体/气态/液态/等离子态 | `Build.mount` 是独立实体（含速度、体型），不是装备栏的一行 |
| 上马/下马花费**等于骑手一半速度**的移动力 | 骑乘切换本身占用移动力，影响首回合可用距离 |
| 骑乘时骑手与坐骑占据相同空间 | 距离模型只需一个标量，无需两个实体位置 |
| 受控坐骑先攻与骑手等值、随骑手意志移动与行动 | 受控坐骑的移动力并入骑手回合预算 |
| 坐骑的"疾走"只能沿直线向可见敌人移动 | "疾走+转向"的组合不可用 |
| **骑乘冲刺（动作）**：坐骑直线移动 ≥30 尺并停止后，用攻击动作发动 **1 次**近战武器攻击，**具有优势** | 复合算子：`min_travel=30` + `attack_count=1`（**覆盖额外攻击**）+ `adv_tiers+1` |
| 骑乘冲刺流程禁止在第 3、4 步之间插入其它行动 | 与 §8 的有序回合模型一致，校验器直接复用 |
| 强制位移或倒地会中断骑乘，落地需 DC10 敏捷豁免 | 打桩下目标不施加，但骑手自身效果可能触发 |
| 多人共骑：坐骑有 4 份骑手空间 | 打桩为单角色，暂不建模 |

**关键：移动力来自坐骑，不是骑手。** 追踪距离时必须用坐骑速度，否则 T1/T4 的循环无法复现。

**拉冲循环的真实约束**：骑乘冲刺要求直线移动 ≥30 尺。在无限场地 + 目标不动的设定下，每一轮都要先从上一轮的攻击位置退开、再重新冲刺——退开与冲刺抢同一份移动力预算。这正是距离追踪存在的意义：它让"每轮都能冲锋"成为需要验证的结论，而不是默认成立。

## 3. 设计原则

1. **投影优先**：任何规则元素在进入模型前，先投影到有限的伤害相关通道，其余信息在边界处丢弃。
2. **裁定外置**：DM / 设计师的解释写进数据文件，不写进代码。
3. **诚实标注**：每个元素带 `status`；未被建模的元素出现在某构筑的依赖链上时，结果必须打标。
4. **出处强制**：每条规则数据必须能指回 `docs/` 原文的具体位置（见 §12）。

---

## 4. 核心抽象：伤害相关投影

任何规则元素 — 不论原文在讲什么 — 在边界处只能投影到以下通道：

```
Projection = {
  adv_tiers:      +n / -n                   // 优势层数（整数，可为负）
  crit_range:     +n                        // 重击范围
  attack_count:   +n                        // 攻击次数
  damage_slots:   [{ slot, expr }]          // 伤害加值，按"槽"归位
  extra_dice:     [{ dice, crit_doubles }]  // 附伤骰
  damage_mult:    expr                      // 伤害倍率
  resource:       { pool, ±n }              // 资源变动
  distance:       ±n / set                  // 位移（v0.2 新增）
}
```

超出这些通道的内容（行动剥夺、非伤害状态、隐匿判定、社交效果）**在投影处即被丢弃**。

**通道集是可增长的。** 建立数据库的过程中若遇到现有通道无法表达的冷门资源或效果，按 §3.4 的原则新增通道并记录变更，而不是塞进已有通道的 `expr` 里。

### 4.1 优势层数必须是整数

「基础/掷骰」章：

> 你在一次掷骰中每有一重优势，便额外骰一个 d20，然后取所有 d20 中的最高值作为骰值……如果在一次掷骰中同时具有优势或劣势，那么将每一重优势与劣势互相抵消。

优势/劣势是**可叠加的整数层数**，不是布尔值。这与主流 5e 不同，从 5e 继承的引擎在这里必然出错。

层数同时是伤害输入：「战斗风格·巨武器战斗」为"每具有一重优势，在命中后便额外增加 3 点伤害"。

## 5. 数据模型

### 5.1 构筑 Build

```jsonc
{
  "meta": { "rules_version": "1.63", "level": 12, "point_buy": 32 },
  "race":    { "id": "race.half_orc", "variant": null },
  "classes": [{ "id": "class.barbarian", "level": 12, "subclass": "path.totem" }],
  "feats":   [{ "id": "feat.kaishan.initiate", "at_level": 1 }],
  "maneuvers": { "known": ["mv.开山流.低级.全身撞击"], "prepared": ["mv.开山流.低级.全身撞击"] },
  "spells":  { "known": [], "prepared": [] },
  "items":   [{ "id": "item.greatsword_plus1" }],
  "scores":  { "base": { "str": 15, "dex": 13, "con": 16, "int": 16, "wis": 10, "cha": 8 } },
  "choices": { "fighting_style": "style.dueling", "rage_heart": "heart.bloodthirst" },
  "variants":[{ "scope": "class.barbarian.rage", "id": "variant.swift_rage", "on": false }]
}
```

`variants` 是**元素级开关**——「疾风狂暴」「爆发式卓越骰」这类玩家可选变体不是新增条目，而是重新定义已有条目。缺少这一层会系统性漏掉一批构筑。

`scores` 只记录购点基础值，其余加值由推导环节计算（与角色卡模板的"初始 / 种族+ / 升级+ / 专长+ / 装备+"分栏一致）。

### 5.2 输出环境 TargetProfile

```jsonc
{
  "targets": [{
    "count": 1, "ac": 18,
    "saves": { "str": 5, "dex": 3, "con": 6, "int": 0, "wis": 2, "cha": 0 },
    "resist": ["fire"], "vuln": [], "immune": [], "absorb": []
  }],
  "initial_distance_ft": 30,
  "terrain": "open",            // open | difficult | restricted
  "rounds": 3,
  "short_rests": 1,
  "prebuff_rounds": 1
}
```

云端草稿列的是「AC、豁免、资源消耗量、输出轮次」四项。实际还需要：目标数量、抗性分布、初始距离、地形、短休次数、准备轮数。**环境不能只有四个标量。**

### 5.3 策略 Strategy：条件策略，不是固定脚本

限次资源的价值依赖于**它花在什么结果上**。因此策略不能是一串固定动作，必须是**带条件的决策规则**。

规则书本身就定义了多个决策时点，实测统计（252 个战技）：

| 时点 | 触发条件 | 实例 |
| --- | --- | --- |
| `before_roll` | 前置消耗，无论结果 | `替换一次攻击` + 掷卓越骰，共 54 条 |
| `after_roll` | 掷骰后、DM 宣布结果前 | 盾牌格挡"你可以在攻击掷骰后、DM宣布结果前使用" |
| `on_hit` | 命中后结算 | "若命中……"共 85 处 |
| `on_miss` | 失手后 | 变招"当你的近战武器攻击失手时……骰一枚卓越骰" |
| `on_crit` | 重击时 | 少量 |

策略的表示形式：

```jsonc
{
  "round": 1,
  "plan": [
    { "op": "attack.basic", "repeat": 2 },
    { "op": "mv.开山流.低级.英勇冲锋", "uses": { "replace_attack": 1 } }
  ],
  "contingency": [
    { "at": "on_miss", "on": "attack.basic#1",
      "do": { "op": "mv.开山流.中级.变招" } },
    { "at": "on_hit", "on": "attack.basic#1",
      "do": { "spend": { "superiority": 1 }, "effect": "extra_dice", "dice": "1d8" } }
  ]
}
```

**二期"求优质策略"因此是求解一个有限期决策问题，而非排序一串脚本。**

### 5.4 算子 Op

```jsonc
{
  "id": "mv.开山流.低级.全身撞击",
  "name": "全身撞击",
  "school": "开山流", "tier": "低级", "kind": "打击技",
  "source": { "book": "5z", "version": "1.63",
              "file": "专长/战技专长/开山流专长.htm", "anchor": "全身撞击" },
  "status": "modeled",
  "ruling": { "by": "DM", "text": "……", "date": "2026-10-25" },
  "cost": { "replace_attack": 1, "superiority": { "first": 1, "repeat": 1 } },
  "decision_point": "before_roll",
  "gate": { "weapon": { "two_handed": true, "melee": true }, "distance": { "max": "reach" } },
  "projection": {
    "damage_slots": [{
      "slot": "总伤害", "expr": "min(target.ac, 50)",
      "ignores": ["weapon_dice", "ability", "flat_mods"],
      "type": "bludgeoning", "crit_doubles": false,
      "requires": "on_hit"
    }]
  }
}
```

三个必须从第一天就写进 schema 的细节：

#### ① 伤害必须是命名槽的字典

「全身撞击」原文："忽略武器伤害骰、属性调整值以及其它伤害加值，伤害总值等于你的 AC（最大为 50 点）"。若伤害只有"骰子 + 固定值"两个数，这条无法表达。

槽字典：`{ 武器骰, 属性, 熟练, 体型, 专长, 战技, 骰池, 其它 }`，每条规则声明它**作用于**哪些槽、**忽略**哪些槽。

#### ② 卓越骰成本是有状态的

> 一部分战技的卓越骰消耗，会写成"A枚（B枚）"的形式……第一次使用这个战技，需要花费 A 枚卓越骰，重复使用则需要花费 B 枚。

实测 252 条中 **92 条**使用这种双值写法。`cost.superiority` 必须携带 `first` / `repeat`。

#### ③ 决策时点是一等字段

见 §5.3。`decision_point` 决定该算子能否进入条件策略，缺失就无法建模资源的最优使用。

## 6. 伤害结算管线

### 6.1 单次攻击：命中率与重击率

```
t_hit  = target.ac - attack_bonus
t_crit = 21 - crit_range                    # 默认 crit_range = 1 → d20 ≥ 20
t_both = max(t_hit, t_crit)                 # 重击必须同时命中

p_hit  = clamp((21 - t_hit)  / 20, 0, 1)
p_both = clamp((21 - t_both) / 20, 0, 1)

n = net_adv_tiers
若 n ≥ 0:  P_hit = 1 - (1 - p_hit )^(n+1);  P_crit = 1 - (1 - p_both)^(n+1)
若 n < 0:  k = -n
           P_hit = p_hit^(k+1);             P_crit = p_both^(k+1)
```

### 6.2 期望伤害

重击只将伤害骰掷两次并相加，不加倍固定加值（除非该槽显式标记 `crit_doubles`）：

```
E = P_hit × ( Σ E[dice] + Σ flat )
  + P_crit × Σ_{crit_doubles=true} E[dice]
```

### 6.3 手册数值只是"命中后伤害"，不是 DPR

**【重要】`【碗】手册` 给出的数字默认全部命中，这是人力计算的简化。本项目必须加权失手率与重击率。**

两者的关系：

```
手册值 ≈ E[damage | hit]        （T1、T2）
手册值 ≈ E[damage | crit]       （T4，原文"一次攻击重击可以造成……"）

而 DPR = P_hit × E[damage | hit] + P_crit × E[dice doubled on crit]
```

推论：**手册数值是 DPR 的上界**。本项目算出的数会系统性低于手册值，这不是错误，是口径差异。回归用例 §5 给出了对应的对拍方法。

### 6.4 目标端结算

伤害按类型分别结算后再求和。顺序由规则书明确规定，不可调整：

```
d0 = Σ 槽（含重击翻倍）
d1 = d0 − Σ 抗性前减伤        # 例："所有伤害减少 5 的魔法灵光"
d2 = 抗性 → 易伤               # 抗性先：floor(d1 / 2)；再易伤：×2；每步向下取整
d3 = d2 − Σ 抗性后减伤        # 例：战斗风格"拦截"
若 吸收：转为等量治疗，伤害取 0    # 吸收优先级高于免疫
否则若 免疫：伤害取 0
```

证据（「基础/伤害与治疗」章）：

- 顺序："抗性先作用于易伤，而两者皆在伤害加上所有适用的调整值后再作应用"。例：25 点钝击、−5 灵光、具抗性 → 先减 5 得 20，再减半得 10。
- 取整："抗性+易伤 = 奇数伤害 −1，偶数伤害不变" → 每步向下取整。
- 两类减伤：灵光类作用于**抗性之前**；"某些能力或特性，在伤害掷骰之后再减少伤害，例如战斗风格'拦截'，此时先计算易伤、抗性，再计算伤害减值"。
- 吸收：优先级高于免疫；"吸收+易伤 = 回复双倍的生命值"。

### 6.5 轮内路径依赖

"本次攻击未命中则下次获得优势""首次命中额外造成伤害"一类效果使攻击间存在依赖。

处理：把一轮内的攻击序列建模为小马尔可夫链，状态为（累积伤害，少量标志位），用精确 DP 求期望。不要假设攻击独立。

## 7. 期望法 与 模拟法

**结论：以期望法为主，蒙特卡洛只作独立校验器。**

### 7.1 为什么期望法可行

1. **随机性维度极低。** 单次攻击的随机结果只有三态：未命中 / 普通命中 / 重击。一轮 k 次攻击的联合结果最多 3^k 个叶子；k=4 → 81，k=8 → 6561，可完全枚举。骰面随机性不需要枚举——伤害对骰子是线性的，取期望即可。

2. **限次资源策略是决策树，不是随机性。** 给定策略后，在每个决策时点用条件期望精确求值，无需采样。

3. **搜索需要确定性。** 三期构筑搜索要评估上万次候选。蒙特卡洛的抽样噪声会让候选间不可比，搜索退化为随机游走。

### 7.2 蒙特卡洛的真实价值

不是算数，是**交叉验证**。两套独立实现（解析引擎 + 模拟器）在同一批回归用例上收敛到同一数值，是发现语义错误最有效的手段。建议：模拟器只跑回归用例，差异超过 1e-3 相对误差即报错。

### 7.3 需要更强工具的情形：限次资源的最优分配

跨多轮、多资源池的分配问题是一个**有限期 MDP**：

```
状态 = (轮次, 剩余资源向量, 距离, 关键标志位)
动作 = 在每个决策时点选择"花费/不花费"及花费对象
目标 = 最大化 E[总伤害]
```

- 状态空间小 → **后向归纳**精确求解。
- 状态空间大 → **LP 松弛**求资源的影子价格，退化为阈值策略（花费当且仅当边际伤害 ≥ 影子价格）。近似，但可解释、可审计，且能给出与精确解的差距上界。

### 7.4 什么时候才真的需要蒙特卡洛

复杂触发链、强非线性的跨攻击依赖。这类情况**应优先用 DP 状态扩张消解**，只有消解失败时才降级到模拟，并在结果上标注 `method: monte_carlo`。

## 8. 动作经济

5z 的动作经济不能建模成"背包"，原因有二：

1. **战技的主干消耗是"替换攻击"。** 注明"替换 X 次攻击"的战技"只能替换攻击动作内的基础攻击次数"。实测 252 条战技中，启动消耗分布为：`1附赠动作` 59、`1反应` 58、`替换一次攻击` 51、`1动作` 50、`替换两次攻击` 8，其余为移动力与组合形态。动作必须建模成**层级结构**：`动作(攻击) → N 个攻击实例`，每个实例可被替换。

2. **禁止插入。** "你不能在执行其它动作的过程中，插入附赠动作"，并给出 5 级狂战士"攻击 → 狂暴 → 额外攻击"的反例。

因此一个回合表示成**有序算子序列 + 条件分支**，并配套校验：

- 同一动作组内的步骤必须连续；
- `replace_attack: k` 必须落在某次攻击动作的剩余攻击实例预算内；
- 每个槽位（动作 / 附赠动作 / 反应 / 交互）每回合各一次。

## 9. 资源时钟

"资源消耗量"不是标量，是一条时间轴：

| 资源池 | 容量来源 | 恢复 | 备注 |
| --- | --- | --- | --- |
| 卓越骰 | 由战技专长累加 | 短休 / 长休**回满** | 骰面 d4；5 级 d6；11 级 d8；17 级 d10 |
| 术法点 | 超魔专长 | 长休 | |
| 法术位 | 职业表 | 长休 | |
| 狂暴次数 | 职业表 | 长休 | 17 级起无限 |
| 超级战技次数 | floor(可用卓越骰 / 10) | 每**两**次长休 | 物品获得的卓越骰不计入 |
| 回合一次类 | 1 | 每回合 | 独立门控，不是池 |

```
短休池：cap_eff = capacity × (short_rests + 1)
长休池：cap_eff = capacity
```

消耗必须同时满足**总量约束**与**每轮门控约束**，且在决策时点受 §5.3 的条件策略支配。

- 新增通道后，重跑回归用例确认无回归。

## 11. 语料处理

### 11.1 三层标注

| 档位 | 内容 | 处理 |
| --- | --- | --- |
| 绿 | 纯数值：加值、骰子、次数、DC、资源上限 | 自动抽取 |
| 黄 | 条件逻辑：触发、替换、条件加成、变体开关 | 人工 / LLM 写成算子 |
| 红 | 叙述性与裁量：位置、视线、互动、DM 判断 | 声明"已抽象掉"，或进入仲裁 |

### 11.2 仲裁工作流

1. 无法确定解释的条目置 `status: unmodeled` 或 `approximated`，写入 `ambiguity`。
2. 队列按 **（对伤害的影响量级 × 在回归用例中出现的频率）** 排序。
3. 裁定写回 `ruling`（裁定人、日期、结论），**不写入代码**。
4. 规则书版本升级后，全部 `ruling` 进入复核。

### 11.3 三条纪律

1. **裁定外置**：代码里不允许出现"因为 DM 说……所以这里 ×2"的硬编码。
2. **诚实标注**：`status` 必须真实反映覆盖情况。
3. **覆盖率驱动**：每个回归用例跑完，输出 = 伤害值 + 实际使用的算子清单 + **跳过的算子清单**。这是防止"静默漏掉 30% 却给出漂亮数字"的唯一手段。

## 12. 溯源：强制

评审确认：**出处标注为算子层的强制字段。**

`形式化/README` 曾把出处标注写作"不作为强制要求"，其目的是**避免多 Agent 协作时的指令冲突**，不是否定溯源的必要性。两者的关系这样处理：

- **治理层**（README、plans/）不预设工作方式，避免与并行协作者的指令打架；
- **数据层**（本方案、Schema）把 `source` 设为必填，由数据校验强制执行。

这样既不给协作者强加流程，又保证数据可追溯。`plans/整体目标.md` §5 的"可追溯到原文"成功标准由此落实。

理由：

- 溯源成本是一个路径字符串；
- v1.63 已修改夹击、狂战士 2 级特性、多处战技数值，后续仍会变动；
- `【碗】手册` 已出现与 v1.63 的脱节（见 [回归用例.md](回归用例.md) §4）；
- DM 仲裁时，裁定必须能指回原文。
