# 方案：打桩伤害链的形式化

> 状态：v0.1（建议稿，待评审） | 依赖：[回归用例.md](回归用例.md)、[决策记录 D-011~D-014](../plans/决策记录.md) | 最后更新：2026-10-23
> 适用规则书版本：`docs/5z规则1.63版.chm`（v1.63，2026-10-21）

本文给出「打击者打桩伤害链」的形式化方案：把规则书中与伤害计算相关的内容，转成可计算、可校验、可审计的结构。

本文只定义**数据模型与语义**，不规定实现方案、目录划分与阶段划分（按 `plans/` 的治理原则，这些在阶段实际创建时再定）。

---

## 1. 为什么要收窄范围

规则书解包后共 **1338 个 HTML 文件**（职业 209、法术 107、怪物 69、专长 67、种族 65、装备 60、世界 42、基础 23、私货未通过 16、范例卡 2），另有 1166 条法术词典。

直接建通用规则引擎不划算，理由有三：

1. **体量**：约 3000 个 crunch 条目，绝大多数是独一无二的自然语言描述。
2. **歧义**：规则书自带 `//` 注释、"疑难解答"章节与"玩家可选变体"，说明边界本身模糊。
3. **版本漂移**：v1.63 仅相对上一版就修改了夹击加值（+3→+2）、狂战士 2 级特性、多处战技与法术数值。一次性编译的产物必然腐烂。

因此本文的立场是：

> **要形式化的不是"5z 规则"，而是"5z 中影响伤害的那个子语言"。**

形式化的第一件事不是选引擎，而是**划定子语言边界**，并让"没划进来的部分"对使用者可见。

## 2. 打桩契约

所有计算结果都条件于以下假设。**这份契约必须随结果一同呈现**，否则数值没有意义。

| # | 假设 |
| --- | --- |
| 1 | 单目标；固定 AC、六项豁免、伤害抗性/易伤/免疫/吸收 |
| 2 | 目标不行动、不还手、不移动、不施加状态、不产生反应 |
| 3 | 距离使用档位（贴身 / 单次移动内 / 远程），不做网格、视线、掩护 |
| 4 | 无掩护、无夹击、无盟友（除非环境显式声明） |
| 5 | 目标初始无状态；攻击者可利用 `prebuff_rounds` 轮进行准备 |
| 6 | **只有构筑付出了代价才施加的状态计入** — 不得无偿获得倒地等状态带来的优势 |
| 7 | 攻击者先手，不掷先攻 |
| 8 | 目标 HP 视为充足（除非需要计算击杀轮数） |
| 9 | 开战时资源为满；战斗期间的短休次数由环境给定 |

### 2.1 第 6 条是公平性锚点

打桩时目标不会抵抗。若不约束，任何构筑都能免费把目标设为倒地、束缚、恐慌以获取优势，结果将失去比较意义。

规则是：**状态必须由构筑中的某个算子以明确的动作/资源代价产生**。

### 2.2 待定：移动依赖的伤害循环

`回归用例` 中的 T1（骑乘冲锋）依赖位移产生伤害。契约第 3 条只说了"距离用档位、不做网格"，未回答这类循环是否计入。

参照手册自身的说法（"即使地形不允许骑冲也有合格的轮伤"），初步建议：位移依赖的循环**作为环境的一个轴**（`terrain_mobility: open | restricted`）显式声明，而不是默认计入或默认排除。

**此项待 DM / 规则设计师确认。**

## 3. 设计原则

1. **投影优先**：任何规则元素在进入模型前，先投影到有限的伤害相关通道，其余信息在边界处丢弃。
2. **裁定外置**：DM / 设计师的解释写进数据文件，不写进代码。规则书升级时裁定可被批量复核。
3. **诚实标注**：每个元素带 `status`；未被建模的元素出现在某构筑的依赖链上时，结果必须打标，而不是照样给数。

---

## 4. 核心抽象：伤害相关投影

任何规则元素 — 不论原文在讲什么 — 在边界处只能投影到以下 **7 个通道**：

```
Projection = {
  adv_tiers:      +n / -n                   // 优势层数（整数，可为负）
  crit_range:     +n                        // 重击范围
  attack_count:   +n                        // 攻击次数
  damage_slots:   [{ slot, expr }]          // 伤害加值，按"槽"归位
  extra_dice:     [{ dice, crit_doubles }]  // 附伤骰
  damage_mult:    expr                      // 伤害倍率（罕见）
  resource:       { pool, ±n }              // 资源变动
}
```

超出这 7 个通道的内容（位移、行动剥夺、非伤害状态、互动、隐匿判定、社交效果）**在投影处即被丢弃**，不进入模型。

这条原则是整套方案能收敛的根本原因：242 个战技中，绝大多数只用到其中 1–2 个通道。

### 4.1 优势层数必须是整数

规则书「基础/掷骰」章明确：

> 你在一次掷骰中每有一重优势，便额外骰一个 d20，然后取所有 d20 中的最高值作为骰值……如果在一次掷骰中同时具有优势或劣势，那么将每一重优势与劣势互相抵消。

因此优势/劣势是**可叠加的整数层数**，不是布尔值。这与主流 5e 不同，任何继承自 5e 的引擎在这里都会出错。

层数同时是伤害的输入：「战斗风格·巨武器战斗」为"每具有一重优势，在命中后便额外增加 3 点伤害"，是层数的线性函数。

## 5. 数据模型

### 5.1 构筑 Build

```jsonc
{
  "meta": { "rules_version": "1.63", "level": 12, "point_buy": 32 },
  "race":    { "id": "race.half_orc", "variant": null },
  "classes": [{ "id": "class.barbarian", "level": 12, "subclass": "path.totem" }],
  "feats":   [{ "id": "feat.kaishan.initiate", "at_level": 1 }],
  "maneuvers": { "known": ["mw.allout_slam"], "prepared": ["mw.allout_slam"] },
  "spells":  { "known": [], "prepared": [] },
  "items":   [{ "id": "item.greatsword_plus1" }],
  "scores":  { "base": { "str": 15, "dex": 13, "con": 16,
                         "int": 16, "wis": 10, "cha": 8 } },
  "choices": { "fighting_style": "style.dueling", "rage_heart": "heart.bloodthirst" },
  "variants":[{ "scope": "class.barbarian.rage", "id": "variant.swift_rage", "on": false }]
}
```

**`variants` 是元素级开关。** 规则书存在"玩家可选变体"，例如狂战士的「疾风狂暴」、卓越骰的「爆发式卓越骰」。这类变体不是新增独立条目，而是**重新定义已有条目**。缺少这一层会系统性漏掉一批构筑。

**`scores` 只记录购点基础值。** 种族、升级、专长、装备带来的加值由推导环节计算，不写入构筑 — 与规则书角色卡模板的分栏一致（初始 / 种族+ / 升级+ / 专长+ / 装备+）。

### 5.2 输出环境 TargetProfile

```jsonc
{
  "targets": [{
    "count": 1,
    "ac": 18,
    "saves": { "str": 5, "dex": 3, "con": 6, "int": 0, "wis": 2, "cha": 0 },
    "resist": ["fire"], "vuln": [], "immune": [], "absorb": []
  }],
  "range_band": "engage",        // engage | move | ranged
  "terrain_mobility": "open",    // 见 §2.2，待确认
  "rounds": 3,
  "short_rests": 1,
  "prebuff_rounds": 1
}
```

云端草稿列的是「AC、豁免、资源消耗量、输出轮次」四项。实际还需要：目标数量、抗性/易伤分布、距离档位、短休次数、准备轮数。**环境不能只有四个标量。**

### 5.3 策略 Strategy

```jsonc
[
  { "round": 0, "steps": [
      { "op": "buff.rage" },
      { "op": "buff.reckless_attack" } ] },
  { "round": 1, "steps": [
      { "op": "attack.basic", "repeat": 2 },
      { "op": "mw.allout_slam" } ] }
]
```

**分工**：构筑决定"可用算子集 + 资源总量"，策略决定"在时间轴上怎么排"。这是云端草稿中"两个因变量"的形式化接口。

### 5.4 算子 Op

```jsonc
{
  "id": "mw.allout_slam",
  "name": "全身撞击",
  "source": {
    "book": "5z", "version": "1.63",
    "path": "专长/战技专长/开山流专长.htm#全身撞击"
  },
  "status": "modeled",   // modeled | approximated | unmodeled | out_of_scope
  "ruling": { "by": "DM", "text": "……", "date": "2026-10-25" },
  "cost": { "replace_attack": 1, "superiority": { "first": 1, "repeat": 1 } },
  "gate": { "weapon": { "two_handed": true, "melee": true },
            "range_band": "engage" },
  "projection": {
    "damage_slots": [{
      "slot": "总伤害",
      "expr": "min(target.ac, 50)",
      "ignores": ["weapon_dice", "ability", "flat_mods"],
      "type": "bludgeoning",
      "crit_doubles": false
    }]
  }
}
```

三个必须从第一天就写进 schema 的细节：

#### ① 伤害必须是命名槽的字典，不是 `dice + flat`

「全身撞击」原文为"忽略武器伤害骰、属性调整值以及其它伤害加值，伤害总值等于你的 AC（最大为 50 点）"。若伤害只有"骰子 + 固定值"两个数，这条无法表达。

伤害定义为命名槽字典：`{ 武器骰, 属性, 熟练, 体型, 专长, 战技, 骰池, 其它 }`，每条规则声明它**作用于**哪些槽、**忽略**哪些槽。

#### ② 卓越骰成本是有状态的

> 一部分战技的卓越骰消耗，会写成"A枚（B）枚"的形式，这表明你在一场战斗中第一次使用这个战技，需要花费 A 枚卓越骰，重复使用则需要花费 B 枚。

`cost.superiority` 必须携带 `first` / `repeat` 两个值，成本是使用历史的函数，不是常量。

#### ③ 优势贡献必须标注来源与层数

「巨武器战斗」的 `3 * net_adv_tiers` 要求层数在求值时可加、可抵消、可查询。

## 6. 伤害结算管线

### 6.1 单次攻击

```
t_hit  = target.ac - attack_bonus
t_crit = 21 - crit_range                    # 默认 crit_range = 1 → d20 ≥ 20
t_both = max(t_hit, t_crit)                 # 重击必须同时命中

p_hit  = clamp((21 - t_hit)  / 20, 0, 1)
p_both = clamp((21 - t_both) / 20, 0, 1)

n = net_adv_tiers                           # 优劣势抵消后的净层数
若 n ≥ 0:  P_hit = 1 - (1 - p_hit )^(n+1)
           P_crit = 1 - (1 - p_both)^(n+1)
若 n < 0:  k = -n
           P_hit = p_hit^(k+1)
           P_crit = p_both^(k+1)
```

### 6.2 期望伤害

重击只将伤害骰掷两次并相加，不加倍固定加值（除非该槽显式标记 `crit_doubles`）：

```
E = P_hit × ( Σ E[dice] + Σ flat )
  + P_crit × Σ_{crit_doubles=true} E[dice]
```

**采用期望值而非随机模拟。** 依据：`【碗】手册` 的范例卡全部按骰子期望求和给出（见 [回归用例.md](回归用例.md)），这既是社区既有口径，也可直接与回归用例对拍。

### 6.3 目标端结算

伤害**按类型分别结算**后再求和 — 抗性/免疫/吸收都是按类型的。顺序由规则书明确规定，不可调整：

```
d0 = Σ 槽（含重击翻倍）
d1 = d0 − Σ 抗性前减伤        # 例："所有伤害减少 5 的魔法灵光"
d2 = 抗性 → 易伤               # 抗性先：floor(d1 / 2)；再易伤：×2
                               #   每一步向下取整
d3 = d2 − Σ 抗性后减伤        # 例：战斗风格"拦截"
若 吸收：转为等量治疗，伤害取 0    # 吸收优先级高于免疫
否则若 免疫：伤害取 0
```

**证据引用**（「基础/伤害与治疗」章）：

- 顺序："抗性先作用于易伤，而两者皆在伤害加上所有适用的调整值后再作应用"。
  例：25 点钝击、所有伤害减少 5 的灵光、具抗性 → 先减 5 得 20，再减半得 10。
- 取整："抗性+易伤 = 奇数伤害 −1，偶数伤害不变" → 每一步向下取整。
- 两类减伤：上述灵光类作用于**抗性之前**；"某些能力或特性，在伤害掷骰之后再减少伤害，例如战斗风格'拦截'，此时先计算易伤、抗性，再计算伤害减值"。因此必须区分 `pre_resist_reduction` 与 `post_resist_reduction` 两个独立槽。
- 吸收：优先级高于免疫；"吸收+易伤 = 回复双倍的生命值"。

### 6.4 轮内路径依赖

存在"本次攻击未命中则下次获得优势""首次命中额外造成伤害"一类效果，攻击之间存在依赖。

**处理方式**：将一轮内的攻击序列建模为**小马尔可夫链**，状态为（累积伤害，少量标志位），用精确 DP 求期望。不要假设攻击相互独立 — 那会引入系统误差，而状态维度很小，DP 成本可忽略。

### 6.5 示意演算

数值仅用于演示管线形状，不代表真实评测结果。

设：12 级狂战士，力量 17（+3），熟练加值 +4，巨剑（2d6），目标 AC 18，鲁莽攻击（1 重优势）。

```
attack_bonus = 3 + 4 = 7
t_hit  = 18 - 7 = 11        p_hit  = (21-11)/20 = 0.50
t_crit = 21 - 1 = 20        p_both = max(11,20) = 20 → 0.05

n = 1（一重优势）
P_hit  = 1 - 0.5²   = 0.7500
P_crit = 1 - 0.95²  = 0.0975

伤害槽：武器骰 2d6 = 7.0｜属性 +3｜狂暴 +4
E[dice] = 7.0,  flat = 7

E = 0.75 × (7.0 + 7) + 0.0975 × 7.0
  = 10.50 + 0.6825
  = 11.18  （单次攻击）
```

## 7. 动作经济

5z 的动作经济**不能被建模成"背包"**（1 动作 + 1 附赠动作 + 1 反应），原因有二：

1. **战技的主干消耗是"替换攻击"**。规则书：注明"替换 X 次攻击"的战技"只能替换攻击动作内的基础攻击次数"。因此动作是**层级结构**：`动作(攻击) → N 个攻击实例`，每个实例可被替换。
2. **禁止插入**。规则书明确："你不能在执行其它动作的过程中，插入附赠动作"，并给出 5 级狂战士"攻击 → 狂暴 → 额外攻击"的反例。

因此一个回合必须表示成**有序的算子序列**，并配套校验：

- 同一动作组内的步骤必须连续（不可被附赠动作打断）；
- `replace_attack: k` 必须落在某次攻击动作的剩余攻击实例预算内；
- 每个槽位（动作 / 附赠动作 / 反应 / 交互）每回合各一次。

建议采用**扁平列表 + 显式 `parent` 指针**的表示，由校验器检查，而不是写一套形式文法 — 前者更容易人工编写与 diff。

## 8. 资源时钟

"资源消耗量"不是一个标量，而是一条时间轴。各资源池的恢复节奏不同：

| 资源池 | 容量来源 | 恢复 | 备注 |
| --- | --- | --- | --- |
| 卓越骰 | 由战技专长累加 | 短休 / 长休**回满** | 骰面 d4；5 级起 d6；11 级起 d8；17 级起 d10 |
| 术法点 | 超魔专长 | 长休 | |
| 法术位 | 职业表 | 长休 | |
| 狂暴次数 | 职业表 | 长休 | 17 级起无限 |
| 超级战技次数 | floor(可用卓越骰 / 10) | 每**两**次长休 | 通过物品获得的卓越骰不提供超级战技次数 |
| 回合一次类 | 1 | 每回合 | 是独立门控，不是池 |

有效容量按时间轴展开：

```
短休池：cap_eff = capacity × (short_rests + 1)
长休池：cap_eff = capacity
```

资源消耗必须同时满足**总量约束**与**每轮门控约束**。

## 9. 语料与抽取

### 9.1 三层标注

| 档位 | 内容 | 处理 |
| --- | --- | --- |
| 绿 | 纯数值：加值、骰子、次数、DC、资源上限 | 从表格自动抽取 |
| 黄 | 条件逻辑：触发、替换、条件加成、变体开关 | 人工 / LLM 写成算子 |
| 红 | 叙述性与裁量：位置、视线、互动、DM 判断 | 显式声明"已抽象掉"，或进入仲裁 |

### 9.2 抽取分层

```
CHM
 └─► 原始 HTML（保留文件路径，即溯源锚点）
      └─► A 档：模板字段正则抽取
            · 战技头（流派·级别·类别 / 武器媒介 / 卓越骰 / 启动消耗 / 目标 / 持续时间）
            · 法术词典 xlsx（1166 条，已有 14 列结构）
            · 职业表（等级 → 特性 / 数值列）
           └─► B 档：效果正文 → 投影（LLM 编译 + 严格 schema 校验）
                └─► C 档：仲裁队列 → DM / 规则设计师裁定 → 写回 ruling
```

242 个战技的头部是**强模板**，A 档抽取精度最高，建议作为整条流水线的验证样例。

### 9.3 仲裁工作流

1. B 档编译时，无法确定解释的条目置 `status: unmodeled` 或 `approximated`，并写入 `ambiguity` 说明。
2. 队列按 **（对伤害的影响量级 × 在回归用例中出现的频率）** 排序。
3. 裁定结果写回 `ruling` 字段（裁定人、日期、结论），**不写入代码**。
4. 规则书版本升级后，全部 `ruling` 进入复核。

### 9.4 三条纪律

1. **裁定外置**：代码里不允许出现"因为 DM 说……所以这里 ×2"的硬编码。
2. **诚实标注**：`status` 必须真实反映覆盖情况。
3. **覆盖率驱动**：每个回归用例跑完，输出 = 伤害值 + 实际使用的算子清单 + **跳过的算子清单**。这是防止"静默漏掉 30% 却给出漂亮数字"的唯一手段。

## 10. 溯源

`整体目标` §5 把"规则数据可追溯到 `docs/` 中的原文，并有歧义裁定记录"列为成功标准，但 `形式化/README` 把出处标注描述为"不作为强制要求"。两者存在冲突。

**建议按 §5 执行，将 `source` 设为算子层的强制字段。** 理由：

- 溯源成本是一个路径字符串；
- 规则书 v1.63 已修改夹击、狂战士 2 级特性、多处战技数值，后续仍会变动；
- `【碗】手册` 已出现与 v1.63 的脱节（详见 [回归用例.md](回归用例.md) 第 4 节）；
- DM 仲裁时，裁定必须能指回原文。
