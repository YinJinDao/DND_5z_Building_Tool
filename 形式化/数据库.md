# 规则数据库：约定与结构

> 状态：v0.1 | 依赖：[方案-打桩伤害链.md](方案-打桩伤害链.md) | 最后更新：2026-10-23
> 适用规则书版本：v1.63（2026-10-21）

本文件定义规则数据库的存储格式、字段约定、ID 规则与演进方式。

---

## 1. 基本原则

1. **可 diff、可评审**。规则项目的主要成本是评审而非查询。数据用 JSONL（一行一条），便于 code review 与按行讨论。
2. **原始语料不入库**。CHM 解包后约 140 MB / 1338 个 HTML 文件，不提交进仓库；只保留 `docs/` 中的 CHM 与可复现的抽取脚本。
3. **出处用锚点，不用副本**。`source.file` 指 CHM 内部路径，`source.anchor` 指条目名，二者合起来定位原文。
4. **派生格式按需生成**。SQLite / 内存索引都是派生产物，不作为源。

## 3. 字段约定

### 3.1 所有记录共有

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 稳定标识，见 §4 |
| `name` | string | 中文名，与原文一致 |
| `source` | object | 出处，见 §3.2，**必填** |
| `status` | enum | `extracted` / `compiled` / `modeled` / `approximated` / `unmodeled` / `out_of_scope` |
| `notes` | string[] | 数据质量注记（字段名不一致、表格被压平等） |

### 3.2 `source`

```jsonc
{
  "book": "5z",
  "version": "1.63",
  "file": "专长/战技专长/开山流专长.htm",
  "anchor": "全身撞击",
  "sheet": null,           // xlsx 来源时填工作表名
  "note": "……"             // 版本落差等风险说明
}
```

**`source` 为必填字段。** 治理层（`README`、`plans/`）不预设工作方式以免与并行协作者冲突，但数据的可追溯性由本文件的字段约定强制保证。

### 3.3 A 档与 B 档的边界

- **A 档**（`data/*.jsonl`）：只做**模板字段的结构化**，正文原样保留在 `effect` 中，不做语义解释。
- **B 档**（`ops/*.json`）：把正文编译成算子，含 `projection`、`cost`、`gate`、`decision_point`。
- A 档记录被编译后，`status` 由 `extracted` 变为 `compiled` / `modeled`，但**记录本身不删除**——保留原文是溯源的基础。

## 4. ID 规则

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| 战技 | `mv.<流派>.<级别>.<名称>` | `mv.开山流.低级.全身撞击` |
| 法术 | `sp.<名称>` | `sp.冻寒之触` |
| 算子 | `<前缀>.<来源>.<名称>` | `style.dueling`、`buff.rage` |

ID 一经分配不随规则改名而变；规则书改名时保留可读性更强的旧 ID，并在 `notes` 中记录改名。

**唯一性由抽取脚本校验**，发现重复即报错。

### 5.1 战技表字段

| 字段 | 说明 |
| --- | --- |
| `school` / `tier` / `kind` | 流派 / 级别 / 类别（打击技、强化技、应对技） |
| `weapon_medium` | 武器媒介原文 |
| `superiority` | `{first, repeat, raw}`；`A枚（B枚）` 解析为首次/重复两值 |
| `cost` | 结构化启动消耗：`action` / `bonus_action` / `reaction` / `replace_attack` / `movement_ft` / `free`，并保留 `raw` |
| `target` / `duration` | 原文 |
| `flavor` / `effect` | 风味描述与效果正文（按首段启发式切分，B 档再校正） |
| `raw_fields` | 原文键值，供回溯 |

### 5.2 专长表字段

| 字段 | 说明 |
| --- | --- |
| `categories` / `sources` | 分类与全部出处；同一专长跨分类出现时合并为一条 |
| `prerequisite` / `prerequisite_list` | 先决条件原文与拆分结果，用于构筑约束图 |
| `is_variant` | 是否为「玩家可选变体」条目 |
| `flavor` / `effect` / `body` | 风味、效果与完整正文 |

专长页**没有模板字段**，名称识别依赖版式（整段 14pt 粗体、≤20 字、无句读）。这一约束需要随规则书版式变化而复核。

### 5.3 相关性分诊

`data/relevance.jsonl` 记录每条数据的初筛等级（A/B/C）、信号类别与分值，由 `tools/screen_relevance.py` 生成。

**初筛只用于排队，不是判定。** B 档编译与 DM 裁定才是判定，结果写回算子的 `status`。

### 5.4 已发现的语料问题

| 问题 | 影响 | 处理 |
| --- | --- | --- |
| 2 条战技用「启动时间」而非「启动消耗」 | 抽取器解析失败 | 加别名归一化，记入 `notes` |
| 10 条战技无卓越骰字段 | 无 | 属超级战技，按规则确实不耗卓越骰 |
| 12 个专长跨分类重复出现 | 会污染构建约束图 | 按名称合并，保留全部 `sources` |
| 专长名被版式拆成碎片（如「黯星」+「降临」） | 产生假条目 | 改为整段判定，要求粗体覆盖整段 |
| 法术词典 xlsx 为 1.49 版，规则书为 1.63 | 数据过时 | **已弃用 xlsx，改读 `法术/法术详述/<N>环.htm` 正文**；实测 xlsx 1164 条 vs 正文 1103 条，61 条为旧版残留 |
| 职业特性名与专长名只能靠 14pt 粗体版式识别 | 排版一变即失效 | 每次规则书升级必须重跑并抽查 |
| 职业表在 HTML 中是扁平的（每格一行） | 等级→特性映射未入库 | 解析原始 `<table>`，不走文本转写 |
| 效果正文中的表格被压成单元格逐行 | B 档编译困难 | 直接从原始 HTML 的 `<table>` 解析，或人工整理 |

## 6. 通道演进日志

规则书存在冷门资源与效果，无法在写代码前全部预见。当现有投影通道无法表达时：

1. **新增通道**，而不是把特例塞进已有通道的 `expr` 字符串；
2. 在本节登记变更；
3. 重跑回归用例，确认无回归。

| 日期 | 变更 | 原因 |
| --- | --- | --- |
| 2026-10-23 | 初版 7 通道：`adv_tiers` / `crit_range` / `attack_count` / `damage_slots` / `extra_dice` / `damage_mult` / `resource` | 方案 v0.1 |
| 2026-10-23 | 新增 `distance`（位移） | 评审确认需追踪相对距离，冲锋类战技依赖位移 |

## 7. 复现

```bash
# 需 Windows（hh.exe 解包 CHM）
python -I 形式化/tools/extract_maneuvers.py
python -I 形式化/tools/extract_spells.py
```

脚本会把 CHM 解包到 `.cache/chm/`（已 gitignore），已解包则复用。
