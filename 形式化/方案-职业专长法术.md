# 方案：职业能力 / 专长 / 法术的形式化

> 状态：v0.1（建议稿，待评审） | 依赖：[方案-打桩伤害链.md](方案-打桩伤害链.md)、[数据库.md](数据库.md) | 最后更新：2026-10-23
> 适用规则书版本：v1.63（2026-10-21）

打击者的伤害不来自单一来源。除战技外，职业能力、专长、法术都是构筑的组成部分。本文给出这三类的形式化方案，与战技方案并列。

---

## 1. 三类与战技的结构差异

战技是**模板化**的：六个固定字段（武器媒介 / 卓越骰 / 启动消耗 / 目标 / 持续时间 / 类别）几乎覆盖了它全部的机读信息。另外三类不是。

| 类型 | 字段模板 | 层级 | 名称识别 | 规模 |
| --- | --- | --- | --- | --- |
| 战技 | **强**：6 个固定字段 | 流派 × 级别 × 类别 | 第 2 行匹配 `流派·级别·类别` | 252 |
| 法术 | **强**：环阶行 + 5 个固定字段 | 0–9 环 | 下一行匹配 `戏法/一~九环` | 1103 |
| 职业能力 | **弱**：仅名称 + 正文 | 职业 → 子职 → 特性 | 版式（整段 14pt 粗体） | 512 |
| 专长 | **弱**：名称 + 先决条件 + 正文 | 7 个分类 | 版式（整段 14pt 粗体） | 672 |

结论：**抽取方法必须分开，但落到同一个算子模型。** 差异只在 A 档抽取器；B 档之后完全统一。

---

## 2. 统一算子模型

四类元素编译成同一种 `Op` 记录。相对战技方案（[方案-打桩伤害链.md](方案-打桩伤害链.md) §5.4），新增一个必填字段：

```jsonc
{
  "id": "cf.狂战士.鲁莽攻击",
  "kind": "class_feature",          // class_feature | feat | spell | maneuver
  "acquisition": {                   // ← 新增：构筑如何取得它
    "type": "class_level",
    "class": "狂战士",
    "level": 4,
    "subclass": null
  },
  "cost": { "passive": true },
  "decision_point": "self_turn_start",
  "gate": { "state": ["melee_attack_declared"], "distance": { "max": "reach" } },
  "projection": {
    "adv_tiers": { "self_attack": 1 },
    "disadvantage_on_defense": 1,
    "until": "next_turn_start"
  },
  "source": { "file": "职业/狂战士.htm", "anchor": "鲁莽攻击" },
  "status": "modeled"
}
```

`acquisition` 的四种形态：

| `type` | 字段 | 说明 |
| --- | --- | --- |
| `class_level` | `class`, `level`, `subclass` | 职业/子职特性，等级门槛决定何时可用 |
| `feat_slot` | `prerequisite[]`, `slot_level` | 专长位；先决条件构成构筑约束边 |
| `spell_access` | `class_list[]`, `level`, `prepared` | 法术的已知/准备与环阶 |
| `maneuver_slot` | `known`, `prepared`, `dice_cost` | 战技的准备位与卓越骰成本 |

**`acquisition` 是四类统一的关键。** 没有它，三类只有"效果"没有"取得代价"，构筑搜索的约束图就建不起来。

## 3. 职业能力

### 3.1 范围

仅规则书标注**打击者**定位的 9 个玩家职业：

> 圣武士、奇械师、契术师、武僧、法师、游侠、灵能武士、狂战士、盗贼

（规则书「职业」各页的"定位"小节给出该标注；另有"非玩家职业"页亦标注打击者，不在范围内。）

### 3.2 层级

```
职业（9）  →  主职特性（184）   等级门槛由正文"第 X 级起"或职业表给出
           →  子职（若干）      →  子职特性（328）
```

子职选择本身是一个 `choice`：第 3 级选定后不可更改，其余特性随之解锁。

### 3.3 三类特殊结构

**(a) 选择类特性。** 「战斗风格」「狂暴之心」「原初道途」等不是独立特性，而是**在若干选项中择一**。形式化为：

```jsonc
{ "kind": "choice", "id": "cf.狂战士.战斗风格",
  "options": ["style.dueling", "style.great_weapon", "..."],
  "pick": 1, "irrevocable": true }
```

构筑的 `choices` 字段记录实际选择；搜索时这是一个分支点。

**(b) 玩家可选变体。** 「疾风狂暴」「爆发式卓越骰」等在规则书里以独立小节出现，但语义是**重定义既有条目**。必须落到 `variants` 开关，不能当新特性（见 D-018 相关讨论）。

**(c) 被动 vs 主动。** 有些特性是纯数值（无甲防御改 AC 公式），有些是主动能力（鲁莽攻击需宣告）。前者直接进 `projection`；后者需要 `cost` 与 `decision_point`。

### 3.4 打击者相关的取舍

仅"影响伤害链路"的特性进入 B 档。判断沿用 §4.2 的判据。典型：

- **进**：鲁莽攻击（造优）、额外攻击（攻击次数）、狂暴伤害加值、哨卫之铭（把伤害转给自己——打桩下几乎无影响，标记 `approximated`）
- **不进**：无甲防御（改 AC）、险境感知（改豁免）——**除非**被某个伤害算子引用（见 §4.3 的特例）

## 4. 专长

### 4.1 筛选原则

专长数量 672，绝大多数与伤害无关。**只形式化影响战斗构筑数值的部分**，其余留在库中不编译。

### 4.2 判据

**纳入（IN）** —— 命中以下任一即进 B 档队列：

| 编号 | 类别 | 说明 |
| --- | --- | --- |
| F1 | 属性 | 属性值/上限/调整值的增减 |
| F2 | 命中 | 攻击加值、优势/劣势层数、攻击检定的重骰 |
| F3 | 伤害加值 | 固定值加成 |
| F4 | 额外伤害骰 | 附加的 NdM 骰 |
| F5 | 重骰 | 伤害骰/攻击骰的重掷或取代 |
| F6 | 重击 | 重击范围扩展、重击触发的额外效果 |
| F7 | 限次效果 | 有次数/冷却的能力本身 |
| F8 | 限次次数 | 增加他人能力的可用次数 |
| F9 | 动作经济 | 额外攻击、附赠动作攻击、替换攻击、动作本身 |
| F10 | 资源池 | 卓越骰/术法点/法术位/狂暴次数的增减 |
| F11 | 解锁与获取 | 额外专长、额外战技、额外法术、放宽或解锁列表 |
| F12 | 位移 | 速度、触及、射程的增减（距离决定可选攻击） |

**排除（OUT）**：

- 纯防御：AC、HP、豁免加值、伤害抗性/免疫
- 社交、探索、技能熟练
- 剧情与画风能力

### 4.3 一个必须记下的特例

**防御数值本身不进入评分，但可能作为其他算子的输入。**

例：「全身撞击」的伤害是 `min(AC, 50)`。此时 AC 不再是防御属性，而是**伤害公式的自变量**，因此提供 AC 的专长会间接进入伤害链路。

处理方式：不把防御专长放进主队列，而是**在 B 档编译某个算子时，反向登记它依赖的输入**。若某算子声明依赖 `ac`，则所有改变 AC 的元素自动进入该构筑的依赖集。这是"按依赖收集"而非"按类别收集"。

### 4.4 拿不准的

判据无法覆盖的情况（例如依赖队友、依赖特定场景的复杂互动）一律进**人工校验队列**，由 DM / 规则设计师裁定，结果写入 `ruling`。不猜。

## 5. 法术

### 5.1 数据源：以规则书正文为准

**不使用 `5z1.49法术词典.xlsx`。** 该表为 1.49 版，落后于规则书 1.63，且只是快速查询表。实测差异：xlsx 有 1164 条，规则书正文 1103 条，**61 条为旧版残留**。

规则书正文的模板：

```
剑刃防护Blade Ward          ← 名称 + 英文名
戏法 防护                    ← 环阶行：戏法 | 一~九环 + 学派 +（仪式）
施法时间：1动作
施法距离：自身
法术目标：无
法术成分：V、S
持续时间：一轮               ← 专注写作"专注，至多 X"
[效果正文]
```

### 5.2 相对战技，法术引入三个新机制

**(a) 豁免型伤害路径。** 战技多为攻击检定，而大量伤害法术走豁免。伤害管线必须新增一条分支：

```
攻击型：   P_hit / P_crit  → 伤害
豁免型：   P_save_fail = 1 - P(save)  → 伤害
           P_save_success → 半伤 或 无伤（由法术文本指定）
           豁免 DC = 8 + 熟练加值 + 关键属性调整值
```

**"豁免成功半伤"必须作为独立字段 `half_on_save`**，不能从文本推断。它直接改变期望值公式：

```
E = P(失败) × E[damage] + P(成功) × (half_on_save ? E[damage]/2 : 0)
```

**(b) 等级成长（scaling）。** 戏法与部分法术随角色等级提升骰数：

> 「冻寒之触」……你到达 5 级时，该法术的伤害变为 2d8，11 级起变为 3d8，17 级起变为 4d8。

形式化为分段函数 `scaling: [{level: 5, dice: "2d8"}, {level: 11, ...}]`。

**(c) 升环（upcast）。** 用更高环位施放时效果增强，通常写为"用 X 环或更高环位的法术位施放时，……"。形式化为 `upcast: {per_level: {...}}`，并影响资源消耗。

### 5.3 施法成本

- `施法时间` 决定 `cost`：1 动作 / 1 附赠动作 / 1 反应 / 更长（长于 1 动作的通常不适用于打桩）。
- `法术位` 是长休池，跨轮次衰减，见方案 §9。
- `专注` 在打桩下只有一个约束：**同一次施法者同时只能维持一个专注法术**。这是构筑内冲突，不是环境限制。

## 6. 四类的抽取现状

| 类型 | 条数 | 脚本 | 状态 |
| --- | --- | --- | --- |
| 战技 | 252 | `tools/extract_maneuvers.py` | A 档完成 |
| 职业能力 | 512（主职 184 / 子职 328） | `tools/extract_classes.py` | A 档完成，46 条缺等级门槛 |
| 专长 | 672 | `tools/extract_feats.py` | A 档完成 |
| 法术 | 1103 | `tools/extract_spells.py` | A 档完成（已改读规则书正文） |

### 6.1 名称识别的共同约束

职业能力与专长都没有模板字段，名称识别依赖**版式**：整段落入 14pt 粗体、长度 ≤ 20~24 字、不含句读标点。

这条约束是脆弱的——规则书排版一旦变化就会失效。**每次规则书版本升级，必须重跑抽取并抽查名称识别结果。**

### 6.2 已知缺口

| 缺口 | 影响 | 计划 |
| --- | --- | --- |
| 46 条职业能力未提取到等级门槛 | 构筑约束图不完整 | 解析职业表补全 |
| 职业表在 HTML 中是扁平的 | 等级→特性映射未入库 | 直接解析原始 `<table>`，不走文本 |
| 法术成分的 `M（材料）` 未结构化 | 对伤害影响小 | 低优先 |
| 施法时间存在 `1 动作` / `1动作` 两种写法 | 归一时易错 | 统一空白后匹配 |
