# 整体目标

> 状态：v0.3（草稿） | 依赖：无 | 最后更新：2026-10-23
> 本文只记录相对稳定的目标、范围与边界。阶段划分和实现方案会频繁调整，不在这里预先固定。

## 1. 项目一句话

在 dnd5z（DND 5e 朱雀私设）跑团背景下，对打击者（菜刀）构筑做可复现的伤害评分，并在此基础上求解特定输出环境下的最优策略与最优构筑。

## 2. 背景与已知问题

- 目标：比较不同构筑在特定规则下的强弱，并找出特定条件下的最优解。
- 已知问题：
  1. **评分标准不易确定**：什么算“强”、按单轮还是多轮、如何处理资源和场景，需要明确定义。
  2. **变量与组合过多**：职业、专长、法术、装备、策略的组合爆炸，难以手工计算。
- 前提工作：先把规则书形式化/建模，使工具程序和 AI 能够使用。规则形式化见 `形式化/`。

## 3. 当前范围

- **角色类型**：仅打击者 / 菜刀，即以输出伤害为主要构筑目的的角色。
- **评分口径**：基于伤害。
- **规则范围**：先覆盖打击者伤害链路所需的规则子集，其余按需扩展。
- **工作方式**：先挑边界清晰、容易验证的部分做通，再逐步扩展；不追求一次覆盖全部规则。

## 4. 当前理解（假设，可随时推翻）

当前设想的输入有三类：

- **输出环境**：敌人 AC、豁免、抗性等（字段待定）；云端草稿进一步把 AC、豁免、资源消耗量、输出轮次视为固定变量。
- **构筑**：人物数据与能力（种族、职业、专长、装备、法术等，待形式化）。
- **策略**：格式化的行动方式（粒度与格式待定）。

云端草稿把“构筑”和“输出策略”称为两个因变量，伤害值是最终评价目标。当前设想的工作分层：

1. **评分**：给定输出环境、构筑、策略，计算一个基于伤害的分数。
2. **策略求解**：给定输出环境和构筑，求分数最高的策略；草稿提出此后可打包为“战斗求解器”。
3. **构筑求解**：给定输出环境，求分数最高的构筑及其策略。
4. **综合评分（草稿四期）**：给定多个输出环境和权重，给出综合能力优秀的构筑及各维度评分。

> 来源：云端方案草稿 `docs/基于通用人工智能的5z打击者构筑优化.docx`（2026-10-23 合并）。
> 注意：以上都只是当前假设，不是固定路线图。阶段数量、边界和顺序都可能调整；实际阶段在 `plans/阶段/` 中按需创建。

## 5. 成功标准

- 评分结果可复现、可解释，能说明分数来自哪些假设与计算。
- 规则数据可追溯到 `docs/` 中的原文，并有歧义裁定记录。
- 在受限空间内，求解结果能与穷举或手工基准对拍。
- 最终能在给定输出环境下给出最优构筑与策略，或明确标注为近似解及其依据。

## 6. 非目标（当前）

- 不做打击者以外的角色定位评分。
- 不做完整的战斗模拟器或跑团平台。
- 不替代 DM 的主观裁定。
- 不预先支持全部规则，只做伤害链路所需子集。
- 不在目标文档里预先确定阶段划分和实现方案。

## 7. 约束与未知

- 规则书资料已在 `docs/`（`5z规则1.63版.chm`、`【碗】5z狂战士、战士手册.docx`、`基于通用人工智能的5z打击者构筑优化.docx`），版本与适用范围待确认。
- 评分的时间窗（单轮 / N 轮 / 整场）、资源假设、期望值还是随机模拟，未定；草稿把“资源消耗量”和“输出轮次”列为固定变量，具体口径仍待确认。
- 输出环境的最小字段集未定。
- 策略的表示粒度未定。
- 是否使用 AI 参与求解、以何种方式参与，未定。
- 交付形态（CLI / Web / 桌面）未定。
- 主要用户和使用场景未定。
